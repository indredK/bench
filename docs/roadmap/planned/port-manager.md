# Port Manager（端口管理）规划功能

> 本文件记录 port-manager 模块**未实现 / 待验证**的功能规划，与 `../product-specs/port-manager.md` 同结构。
> 实现一项即从本文件移除，并同步到产品说明；规划新增功能先写到这里再开发。

## 待实现 / 待优化（Backlog）

- [ ] 清理未使用返回值和死代码（来源：`docs/modules/port-manager/roadmap.md`）。
- [ ] 优化大 PID 集合的进程树构建与刷新开销；当前首屏仅构建合并 owner 路径、子节点按需分页（每页 100），但每次展开仍会取得一份完整 `sysinfo` 快照。
- [ ] 收紧 Kill 的 PID 复用竞态：Unix 后代现逐个在 SIGKILL 前复核原生创建身份，身份改变或不可读时 fail-closed；但检查与 PID 信号发送仍非原子，目标进程和 Windows `taskkill` 也仍以 PID 执行。评估 Linux pidfd、Windows process handle 与 macOS 可用方案，并确保无法安全绑定的目标 fail-closed。

## 待验证（真机）

> 本轮先做静态复核；Windows 真机回归按用户安排延后至本轮目标完成后。macOS Local Network/TCC 与系统通知真机项暂未验收。

- [ ] macOS / Windows：告警首次启用的系统通知权限提示、拒绝后的开关与说明、授权后的 free → occupied 通知、权限撤销后的自动关闭。
- [ ] Windows Remote 真机：验证 DNS / IPv4 / IPv6 直连、拒绝端口和 3 秒超时；静态及 macOS 单元测试不替代 Windows 运行时回归。
- [ ] macOS/Windows 双端：lsof / netstat 解析、kill / taskkill 权限语义、PID 复用（`PID_REUSED`）场景真机验证。
- [ ] 杀进程后自动重扫的最终一致性；断网/无权限环境错误码正确落入结构化结果。
- [ ] 500+ 进程下进程树按需加载、展开延迟、快照成本、IPC 体积与虚拟滚动 DOM 数量验收。

## 远期

## 变更记录

- 2026-10-16：静态审计发现 Unix 进程树会直接向旧快照后代 PID 发 SIGKILL，可能在 PID 复用后误杀无关进程。现对每个后代在发信号前重新读取并比较原生创建身份，身份已变化或不可读时 fail-closed；增加防复用 / 缺失身份回归。根 PID 与信号、后代身份复核与信号仍未原子绑定，Windows `taskkill` 也仍按 PID 查找；保留平台句柄设计及 macOS / Windows 真机验证门禁，不推送。

- 2026-10-16：静态审查发现端口扫描仅靠按钮禁用防重入；移除后重加相同端口时，旧响应可写入新行，扫描期间控制器也允许直接调用 Kill。现增加每端口单飞请求 ID、移除/清空/切换目标时失效令牌，并在界面与控制器拦截扫描期 Kill；补移除重加竞态、重复请求和 Kill 拦截回归。macOS / Windows 真机验证仍待安排。
- 2026-10-16：`lsof` 带错误 stderr 的非零退出显式报告查询错误；父链检测与子树构建加入环保护，避免异常快照导致误报空闲或卡死。
- 2026-10-16：静态性能审查发现批量终止会为每个目标 PID 重建全量父子索引；改为每批共用一次索引，并增加分支/环回归。500+ 进程下快照成本和 UI DOM 性能仍待真机测量，本次未推送。
- 2026-10-16：核对 `sysinfo 0.39.6` API 后发现 `System::new_all()` 已完整刷新进程，调用后再执行 `refresh_all()` 会重复扫描；移除冗余刷新，降低每次查询成本。构造函数行为由本地依赖源码确认，500+ 进程整条链的实际耗时仍待真机测量，本次未推送。
- 2026-10-16：静态审查发现 Windows `netstat -ano` 非零退出会被当作空结果，从而把查询失败误报为空闲；现传播命令失败、监听行缺列与非法 PID 错误，并增加解析回归。Windows 真机输出和错误码映射仍待用户安排环境后验收，本次未推送。
- 2026-10-16：静态审查发现 Kill All 可重复终止跨端口共享 PID，结果只显示在首个端口；补前后端去重、结果映射到全部关联端口、PID 0/缺失扫描身份 fail-closed、100 个唯一目标上限及双语结果文案。并禁用扫描/终止期间重复操作，异步回写检查会话有效性；输入、模式和端口 chip 补本地化辅助技术名称。Port Manager 25 项 Vitest、关键回归 244 项、`lint:fe`、Rust 26 项相关测试和 clippy 通过；macOS/Windows 权限、PID 复用与进程退出行为仍需真机复验，本轮不推送。

- 2026-10-16：完成 Remote 跨平台 TCP 连通检查：以现有 Tokio `TcpStream` 替代外部 `nc`，将 DNS + TCP 总时限限制为 3 秒，支持 IPv4 / IPv6 及可选方括号 IPv6，并拒绝端口 0；IPC 返回形状不变，连接失败仍作为该端口结果而非命令崩溃。补回环监听、IPv6 可用性和非法输入回归，并同步产品规格与设计。Rust 定向 5 项、Port Manager 前端 10 项、Clippy、`cargo fmt --check`、`check:be-cfg`、`lint:fe`、Prettier 和 `git diff --check` 通过；未启动 Bench，Windows 真机回归依用户安排延后，未推送。
- 2026-10-16：静态审查发现占用告警未检查/申请系统通知权限，授权被拒时仅静默丢弃，使开关仍显示已启用；清空列表后开关状态还会残留并自动监控后来新增的端口。现仅在用户主动启用时检查并按需请求权限；拒绝、撤销或投递失败时关闭告警并显示独立本地化说明；移除最后端口、清空或切换模式时也关闭告警，避免后来新增端口意外开始监控，并避免清除/覆盖扫描和 Kill 错误。新增权限与监控范围回归及双语提示；真机系统弹窗及通知投递验收待完成，未推送。
- 2026-10-16：静态复核发现控制器把 Local / Remote 单端口查询的 `detail.error` 映射为 `empty`，可能让用户把查询失败理解为端口空闲；现改为 `error`，补远程连接超时回归。Port Manager 5 个测试文件 36 项、前端全量 560 项、关键回归 244 项、`lint:fe` 与 Clippy 通过；macOS / Windows 错误与通知行为尚未真机复验，未推送。
- 2026-10-16：继续性能复核发现一次添加多个端口时，前端按端口串行发 IPC；Local 每个请求都会重新读取全量进程与 socket 快照，抵消后端“每批一次”优化并拉长等待。现合并为一个批量调用，按每端口请求令牌过滤迟到结果，并把缺行/重复行作为错误处理。又发现 `rescanAll` 会在单飞筛选前统一写入 `waiting`，使仍在途的端口被误显示成未开始；现移除这次抢先状态重置并补并发回归。Port Manager 定向 38 项、前端全量 562 项、关键回归 244 项、`lint:fe` 与 Clippy 通过；500+ 进程及 macOS / Windows 真机行为仍待验收，未推送。
- 2026-10-16：深度复核发现 Kill 防 PID 复用只比较进程名，且 `sysinfo` 的秒级时间仍可能让同一秒内同名进程复用 PID 时碰撞。现使用 macOS `proc_pidinfo` 微秒时间、Windows `GetProcessTimes` 100ns FILETIME、Linux `/proc` 启动 tick，与 `sysinfo` 秒级快照交叉校验后散列 PID、名称和可执行文件路径；只为端口占用进程取原生时间，身份缺失时拒绝。扫描结果随 ProcessNode 返回，Kill 时用新快照重算身份。增加同名 PID 复用、缺失身份和快照不一致回归，并同步接口、产品规格和设计。后端 735 项（2 项跳过）、前端 567 项、`clippy:be`、`format:be`、`check:be-cfg`、`lint:fe` 通过；macOS/Windows 实机 Kill 与 PID 复用验收仍待完成，未推送。
- 2026-10-16：静态审查发现一个端口由多个 PID 共同占用时，进程树只把第一个 PID 标为“端口所有者”，其余占用进程缺少标记。现传入该端口全部 owner PID 并逐行匹配，补多占用者组件回归；前端全量 564 项、关键回归 244 项、`lint:fe`、Clippy、相关文件 Prettier 与 `git diff --check` 通过。macOS / Windows 真机复验尚未完成，本轮不推送。
- 2026-10-16：Local-only Kill 之前只由 Remote UI 隐藏按钮保证，控制器的单端口 / 全部终止方法没有再次检查模式。现控制器也在 IPC 前拒绝 Remote Kill，避免确认框期间状态变化或内部调用绕过视图约束；新增双方法回归。Remote controller 定向 12 项、前端全量 586 项、`lint:fe`、Prettier 和 `git diff --check` 通过；真机与 OS 权限语义仍待验收，未推送。
- 2026-10-16：静态复核发现占用告警只在端口从空闲变占用时查询通知权限；若用户在系统设置撤销权限而监控端口一直保持空闲或占用，开关会继续显示开启。现每次 30 秒轮询先检查权限；拒绝则自动关闭并显示 revoked 文案，权限状态查询失败也关闭并显示恢复说明；发送前仍再次检查以覆盖轮询期间的权限变化。新增无状态迁移时撤权与权限 API 失败回归；占用告警定向 9 项、前端全量 585 项、`lint:fe`、Prettier 通过。系统设置撤权到 UI 自动关闭的真机时序仍待 macOS/Windows 验收，未推送。
- 2026-10-16：将进程树初始响应从每个 owner 的完整子树改为合并后的祖先路径；展开通过 `query_process_children` 读取并复核父节点身份，每页最多 100 项，支持继续加载与错误重试。定向前端 11 项、前端全量 587 项、Rust 进程树 41 项、`lint:fe`、`check:be-cfg` 通过；Clippy 曾发现测试辅助函数缺少 `cfg(test)`，修复后通过。500+ 进程实机耗时 / DOM 验收仍待完成，未推送。
- 2026-10-16：修复 Unix Kill 忽略后代 `kill` 失败并仍报告成功的问题：改用直接信号系统调用，后代已退出视为完成，其余失败返回 `CHILD_KILL_FAILED` 并在中英文界面提示残留子进程风险。另在杀后代后、终止根 PID 前再次复核根身份，并在 Windows 启动 `taskkill` 前复核。Rust 进程树与 Kill 定向 43 项、Rust 全量 752 项（2 项跳过）、前端全量 587 项、`lint:fe`、Clippy、`check:be-cfg` 通过；PID 校验与信号发送之间仍存在极窄 TOCTOU 窗口，需平台句柄方案和真机验证，未推送。
- 2026-10-16：静态复核发现进程树折叠后重开会用 `next_offset` 请求后续页，却按首屏替换已有子节点，可能丢失前页；现记录首个分页是否成功，仅首次展开请求首屏，重开沿用已加载内容，并补回归。另为首屏可见节点和懒加载返回的直接子节点尽力生成身份快照，展开时能检测同名同父 PID 复用。进程树前端 3 项、前端全量 588 项、Rust 进程树 43 项、Rust 全量 752 项（2 项跳过）、`lint:fe`、Clippy、Prettier、`check:docs` 和 `git diff --check` 通过；真机性能 / PID 行为仍未验收，不推送。
- 2026-10-16：静态复核发现动态进程退出会让 offset 分页跳过后续子进程；IPC 与 UI 状态改用最后 PID 游标，文档同步说明每页新快照下低于游标的新进程需重新扫描，加入快照变化回归。前端全量 600 项 / 103 文件、Rust 全量 768 项（2 项跳过）、`lint:fe`、`clippy:be`、`check:be-cfg`（384 文件）、Rust / Prettier 格式、88 篇 Markdown 链接、`git diff --check` 与前端生产构建通过。macOS / Windows 进程变化和 500+ 进程实机性能仍待验收，不推送。
- 2026-10-16：静态复核发现懒加载进程树未沿已展开祖先路径截断异常 PID 环，可能重复呈现并允许继续展开。现沿递归路径识别重复 PID，循环节点显示双语截断提示且不再提供展开控件；增加延迟页返回祖先 PID 的组件回归并同步产品规格。定向进程树 4 项、前端全量 601 项 / 103 文件、`lint:fe`、Prettier、88 篇 Markdown 链接、`git diff --check` 与前端生产构建通过；Rust 全量 768 项（2 项跳过）、Clippy、Rust cfg / 格式于上一条分页游标改动验证通过。macOS / Windows 真实竞态与 PID 行为仍待验收，不推送。
- 2026-10-16：端口进程查询的 macOS `lsof` / Windows `netstat` 与 Windows `taskkill` 原先没有时间上限，进程查询也完整保留命令输出。现复用受控子进程执行器，查询/终止最多等待 10 秒，输出每路上限 1 MiB；查询超时或可能截断按错误处理，`taskkill` 超时提示重扫核验。端口管理 Rust 定向 43 项与 subprocess 定向 6 项通过，Clippy 通过；Windows 真机仍按用户安排延后，未推送。
- 2026-10-16：继续复核通用超时清理路径，发现 Windows 的 `taskkill` 辅助命令本身用无界同步等待，可能使已超时的请求继续卡住；Unix 的 SIGTERM 也可能被子进程忽略并继续持有输出管道。现将辅助命令等待限为 1 秒后终止其自身；Unix 对隔离进程组直接发送 SIGKILL，确保超时 / 取消时后代也关闭继承的输出管道；新增清理助手超时与忽略 SIGTERM 的后代回归。`test:be` 759 项通过（2 项跳过）、Clippy、Rust cfg（384 文件）、格式检查通过；Windows 终止树行为仍待用户安排的真机回归，不推送。
- 2026-10-16：告警轮询静态复核发现系统通知权限查询等待期间若用户切换 Local/Remote 主机或端口集合，旧目标的网络检查仍会在权限查询返回后发出。现派发前复核目标范围和版本，过期轮询不再产生网络副作用；新增延迟权限查询期间切换目标的回归，并同步产品规格、设计与审计记录。告警 hook 10 项、`test:critical` 244 项、`lint:fe`、文档链接、Prettier 与 diff 检查通过；系统通知与跨平台网络时序真机验收仍待完成，不推送。
