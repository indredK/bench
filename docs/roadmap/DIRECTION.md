# Bench 产品方向与开发路线（2026-11 起）

> 本文件是**当前**方向与路线的唯一入口。旧的 [ROADMAP.md](./ROADMAP.md)（R00–R10）已按 D-023 降级为 backlog，只在重新启动某项时参考；插件化阶段状态仍以 [extension-center roadmap](../modules/extension-center/roadmap.md) 为准。方向性取舍写 [decisions.md](../explanation/decisions.md)（本次：D-043）。

## 1. 一句话

**Bench = macOS 优先的个人桌面工作台：一个很小的核心 + 可更新的插件 + 可更新的命令 + 与外部世界的接入。** 它先对自己好用（个人开发者日常），再谈生态。

## 2. 信息架构（一页地图）

| 区域       | 回答的问题               | 内容                                                                                                        | 版本与更新                                    |
| ---------- | ------------------------ | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| 开发工具箱 | 我手边的小工具在哪？     | 端口管理、环境检测、JSON/Base64/哈希/时间戳/UUID/正则、系统信息                                             | 随 Bench 发布                                 |
| 命令中心   | 常用命令怎么一键跑？     | 我的命令卡片（shell / 提权 / 复制 / 打开）+ **命令市场**                                                    | 每条市场命令有独立版本；安装 · 更新 · 卸载    |
| 插件中心   | 有哪些 Bench 插件？      | 已安装 / 插件市场 / 诊断（沙箱、签名、ACL）                                                                 | 每个插件有独立版本；安装 · 更新 · 启停 · 卸载 |
| 跨端接入   | Bench 怎么连到桌面之外？ | 浏览器扩展、AI 客户端（MCP）、自用原生应用                                                                  | 扩展随 Bench 导出；原生应用走私有 CI Artifact |
| 网络探测   | 网络出了什么问题？       | 基础视角（急救）/ 站点延迟 / 测试 / 安全 / 发现，见 [产品地图](../modules/network-probe/README.md#产品地图) | 随 Bench 发布；高级能力以能力包按需安装       |
| 账号管理   | 多个隔离登录态怎么管？   | 站点、账号、会话保活、登录规则（规则随 command-market 仓库更新）                                            | 规则包可独立更新                              |
| 系统设置   | Bench 与 macOS 怎么调？  | 外观、安全与隐私、系统、高级                                                                                | 随 Bench 发布                                 |

**分层原则**：能随时间独立变化的东西（命令、插件、登录规则）都有自己的版本和更新通道；需要特权或原生 API 的东西留在核心；不属于 Bench 插件体系的接入（扩展 / MCP / 原生应用）单独成区，不混进插件中心。

## 3. 「完整可用」的定义（v1.x 目标线）

满足下面五条，Bench 就是一个可以每天用、可以自己更新的完整软件；之后再做什么由你决定。

1. **能装、能更新、能回退**：Bench 自身更新有可见进度（下载 / 安装 / 重启），可后台继续；失败可重试且不丢进度。
2. **命令与插件各自有版本**：在 Bench 里直接安装、更新、卸载；有更新时入口处有角标。
3. **每个页面一屏可用**：统一标题栏（标题 + 副标题 | 导航 | 操作），1280×800 下核心页面无页面级滚动。
4. **失败可诊断**：网络 / 存储 / 签名类错误带根因（路径、HTTP 状态、校验失败点），不再只有一句「失败」。
5. **文档与代码同源**：每个 feature 有 `docs/modules/<id>/`，方向性取舍进 decisions.md，门禁（lint:fe / test:critical / clippy / be-cfg）全绿才合并。

## 4. 路线

### Now（本轮已完成 → 持续验证）

- 命令中心：页内命令市场、版本 / 更新 / 卸载、本地命令库不可用时的明确提示。
- 插件中心收窄为只管插件；已安装列表内联「更新」。
- 跨端接入独立；统一页面标题栏。
- 应用更新：修复下载进度事件字段（`rename_all_fields`）、进度节流、速度 / 剩余时间、后台继续与右下角状态条。
- 网络探测：页面按产品地图拆为目录 + 标题栏 + 工作区；基础视角改为分段显示。

### Next（下一批，按顺序）

1. **真机验收**：在真实 Tauri 窗口里走一遍更新（旧版 → 新版）、命令安装 / 更新 / 卸载、插件更新；补一份验收记录到各模块 roadmap。
2. **原生应用版本化**：CI 产物携带版本号，Bench 内显示「可更新」。
3. **更新体验补强**：下载断点续传评估（受 tauri-plugin-updater 能力限制，先确认）、发布说明本地化。
4. **Windows 门禁**：P6 Windows release 产物与 smoke；未验证前文案一律写 unsupported / partial。
5. **其余页面一屏化**：账号管理、系统设置高级页的长内容分区 / 分页。

### Later（暂不承诺）

- 第三方插件生态（作者工具链已在 `bench-extension-template`，缺口是审核与分发流程）。
- 网络探测的 agent 节点与多节点测量；能力包体系的签名发布。
- 云同步 / AI Agent 类新品类（按旧发布契约默认不做）。

## 5. 硬约束（做决定前先看）

- **没有 Apple Developer 账号**：macOS 包只能 ad-hoc 签名，**不做公证**（D-010）。Bench 自更新不受影响（minisign 独立于 Apple）；原生应用走本机 CI Artifact，Gatekeeper 是否放行由用户决定。涉及 Developer ID / notarization 的需求一律标「需要账号」，不假装可做。
- **Windows 未签名**；Linux 非目标（D-014）。
- **updater minisign 不可省**：缺 `.sig` / `latest.json` / `SHA256SUMS` 即停止发布。
- **Network Probe 红线**：仅检测、不攻击。
- 外部事实（法规 / 标准 / 第三方接口）先过「可靠信源门禁」。

## 6. 日常工作流

见 [development-workflow.md](../how-to/development-workflow.md) 与 [release-workflow.md](../how-to/release-workflow.md)。一句话：**分支 → 门禁全绿 → PR → CI 全绿 → 合并 → release-please 发版 PR → 合并 → Release Build 产出更新包**。依赖升级优先批量（把同类 Dependabot PR 合到一个分支，一次过 CI），避免严格「必须最新」规则下逐个串行等 CI。
