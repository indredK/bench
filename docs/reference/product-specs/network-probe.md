# Network Probe（网络探测 / 网络急救箱）产品说明

> 本文件是 network-probe 模块的**完备产品规格**。一切功能改动、优化、bug 修复都必须同步更新本文件。
> 自包含、可移植：复制到任何项目或交给任何 AI，可据此完整复刻本模块功能。
> 规划/未完成项见 `../planned/network-probe.md`；详细设计见 `../modules/network-probe/`（design*.md、roadmap.md、defaults.md）。

## 1. 定位

- **独立一级 feature**（`desktopOnly: true`，非 Bench 2.0 主序列，与 2.0 并行旁路），入口：路由 `/network-probe`，侧边栏注册。
- 用途：**网络急救箱 + 专业探测工具链**。对标 360 断网急救箱、NETworkManager、安全探测工具链。硬红线：**只检测、不攻击**（不做 ARP 欺骗攻击 / MITM 注入 / DoS / 爆破）。
- 平台：macOS 主路径（Local Network / 系统能力）；Windows 降级；Linux 非目标。
- 状态口径：模块 1.0 / MVP A+B 已闭环；Post-MVP（测速 · 多节点 · 安全 · 发现）主路径已交付，指纹增强与特权 helper 仍待（见 planned）。

│ 基础：六面板纵向单页；其他：当前 L2 面板     │ 命令日志侧栏        │
│                                          │ (280px, 可折叠)    │
├──────────────────────────────────────────┴───────────────────┤

└──────────────────────────────────────────────────────────────┘

- **L1 顶栏**：logo 圆点 + 标题 + 5 个一级导航按钮（基础/站点延迟/测试/安全/发现）；当前项通过 `aria-current="page"` 向辅助技术暴露。右侧**通用探测原点选择器**（当前只允许本机；Globalping 项标注“多节点专用”，自有 agent 仍标注规划中）和**能力包管理按钮**（打开 PackInstallDialog）。最小窗口宽度下，默认资源与能力包管理收为带 tooltip 和 accessible name 的图标按钮，为五个 L1 留出可见空间；窗口较宽时恢复图标 + 文本。Globalping DNS / Ping / HTTP 在「发现 → 多节点」显式运行；此选择器不会假装替其他面板改路由。
- **标题 + capabilities 横幅**：基础视角显示统一页面标题和说明，其他 L1 显示 `L1 / L2 · platform=… privilege=…`。
- **错误横幅**：`error` 非空时在面板上方显示（红框）。
- **安全授权条（SecurityAuthGate）**：仅 L1=security 时显示——未授权时琥珀色提示 +「确认」按钮；已授权显示「已授权」+「撤销」；授权状态持久化于 localStorage（`network-probe:security-authorized`）。
- **命令日志侧栏**：右侧 280px（折叠为 2.25rem 窄条），滚动展示每次探测的 `invoke` 命令文本 + 结果/取消/耗时摘要（时间戳前缀）；取消 IPC 只记“已受理”，收到探测终态后再记已取消。URL 凭据、路径、query、fragment 和 agent 标签不记录原值；可清空（二次确认）；开合状态持久化于 sessionStorage（`network-probe:side-log-open`）。
- **L2 底栏**：当前 L1 的子面板按钮列表（见下表），Post-MVP 面板带「Post」徽标。基础视角的按钮滚动到同页区块，且当前区块高亮跟随手动滚动；键盘 / 辅助技术激活锚点及区块内的跨区快捷入口会把焦点送到目标区块；其他 L1 的按钮切换单一面板。标题层级为页面 `h1`、当前 L1 面板 `h2`、六个基础区块 `h3`、区块内分组 `h4`。

L1 → L2 映射：

| L1       | L2（子面板）                                                  |
| -------- | ------------------------------------------------------------- |
| basic    | overview · tree · opinion · offline · fix · report            |
| sites    | official · packs                                              |
| test     | ping · dns · tcp · custom · traceroute · mtu · egress · speed |
| security | ports · pollution · pcap · dnssec · whois                     |

- 导航状态（当前 l1 / 各 l1 的 l2）持久化于 sessionStorage（`network-probe:nav`）；恢复时只接受已知 L1 自有键，损坏或未知的 L1 回退至 `basic`，避免原型继承属性被当作路由。基础视角的 `l2ByL1.basic` 表示页内当前区块。旧 `offlineSub` 字段仅兼容已保存会话，不控制当前界面。

### 全局交互与反馈细节

- **bootstrap 加载**：进入 feature 时 single-flight 并行拉取 capabilities / defaults / packs / nodes；各来源成功结果独立写入，单源失败不丢弃其余数据。节点、默认资源与 capabilities / packs 快照分别使用修订号，丢弃启动期间已过期的响应，避免慢 bootstrap 覆盖随后开始的节点操作、默认资源重置或能力包刷新；手动刷新即使失败，也会使旧快照失效。成功重试只清理 bootstrap / 节点注册表错误，不清除其他操作错误。失败时顶部展示 `networkProbe.errors.bootstrapFailed` 和带 loading 状态的「重试」按钮；所有来源成功后清除本次 bootstrap 错误，不阻断其余面板。
- **总览加载失败**：本模块会话首次进入 overview 面板时自动加载一次；离开后重新进入或 React effect 重放也不自动重复请求。本机信息读取失败后保留错误横幅与空态，用户可点击「刷新」重试；手动请求期间刷新按钮禁用。摘要、防火墙和 hosts 检查有任一失败时立即显示错误，但仍等全部并发读取结束后才恢复重试，避免慢请求与新一轮重叠。
- **错误横幅**：`error` 非空时面板上方红框展示，文案优先本地化 `networkProbe.errors.<tool>Failed`，兜底后端 `message`；每个操作开始前 `setError(null)`，结束（成功或失败）后由用例设置或清除，单条错误会随下一次操作被清掉。
- **系统诊断详情**：Traceroute、NTP、局域网服务发现、抓包、TCP、HTTP/TLS 与 Quick Fix 的稳定状态必须本地化；操作系统、网络库与探测器自由文本使用共享 `ProbeSystemDetails` 默认折叠，展开后可读，未知状态使用本地化兜底。Traceroute 初始空态只在未运行时显示；已运行的 unavailable / cancelled / 零跳点结果显示终态，不再提示“尚无跳点”。
- **每工具 loading 独立 + 防重入**：`loading*`（每工具一个）为真时对应「运行」按钮禁用并显示运行中文案（如「Ping → 探测中…」）；use-case 入口统一 `if (store.loadingX) return` 短路，同一工具不可并发、不同工具可并行。无 loading 标志的动作（如刷新网络服务、打开系统设置）无禁用态。
- **节点注册表操作**：刷新、新增和移除共享 `loadingNodes` single-flight 状态；操作期间相关按钮和输入框禁用并显示「处理中…」。agent 标签去除首尾空白后须为 1–80 个 Unicode 字符，且不得包含控制字符；前后端均校验，前端即时显示双语错误。HTTPS/WSS endpoint 最多 2048 个 UTF-8 字节，前端按字节数即时校验并阻止提交，后端再次校验；同标签 + 规范化 URL 的重复新增返回现有节点。注册表最多 256 个 agent、JSON 文件最多 1 MiB；读取时先做有界读取并验证条目上限，超限 fail-closed；旧文件超限时启动错误会在全模块可见、提供重试按钮并显示双语恢复提示，节点刷新失败也显示同一恢复说明，避免用户只看到通用加载失败；新增超出条目上限时在健康检查前立即显示双语提示，重复注册仍保持幂等。注册表读改写串行执行并通过原子替换持久化，避免重复点击造成重复条目或损坏 JSON。新增成功时直接用 `addAgent` 返回的健康检查结果 upsert 当前节点，不再重复检查所有 HTTPS/WSS endpoint；若节点列表尚未初始化或为空，则刷新一次以恢复本机和 Globalping 默认节点。移除成功时只过滤目标 agent，保留其他节点的当前可达状态；显式「刷新节点」才重新检查所有 endpoint。
- **能力降级**：`toolEnabled=false`（status 为 `unsupported`/`missing_pack`）时按钮禁用并显示 toolDisabled 提示（`{{tool}} status={{status}} — 已按能力矩阵禁用`）；缺 pack 的工具给出「管理能力包」入口跳转 PackInstallDialog。
- **主动探测结果空态**：测试面板初次打开且无结果时显示本地化引导；请求运行中隐藏空态，失败时只保留所属工具的错误反馈，能力不可用或测速源未就绪时不显示无法执行的引导。自定义目标结果的 `host` / `url` 类型标签本地化，未知类型使用本地化兜底。
- **命令日志侧栏**：每个探测 / 修复命令追加时间戳日志（`appendCommandLog`），运行中/成功/失败/取消均有摘要；取消 IPC 只显示“已受理”，不提前声称探测已取消；可折叠（sessionStorage 记忆）、清空需二次确认。
- **键盘**：各面板均为表单 + 按钮触发（Enter 提交表单）；无全局快捷键（见 §9）。

## 3. 基础（basic）L1

### 3.1 网络概览 overview

- 本模块会话首次进入自动拉取一次；失败后离开再返回不触发新的自动请求，只有用户点击「刷新」才重试。信息卡网格：IPv4 / IPv6 / 网关 / DNS 服务器 / Wi-Fi（SSID + dBm）/ 防火墙状态 / hosts 可疑条目数 / 非回环接口数；列数按卡片可用宽度自动调整，单卡最小宽度 9rem，避免窄窗下将 IPv4 地址拆成孤立字符。macOS `route` / `scutil` / `airport` 命令固定 C locale、最多等待 2 秒、输出最多读取 1 MiB；辅助命令失败或超限时相应可选卡片为空，并显示本地化的部分数据提示；无网关或未连接 Wi-Fi 不当成读取失败。
- 按钮：刷新、打开系统网络设置。数据源 `getLocalNetworkSummary` + `getFirewallStatus` + `checkHostsOverrides`。

### 3.2 体检树 tree（L0–L3 健康扫描）

- 点击「运行体检」→ 后端 `runHealthScan` 逐项流式推送 `health-item` 事件，面板按层分组（L0 网络层 / L1 网关 / L2 DNS / L3 公网）实时渲染；每项优先显示按当前语言本地化的检查名称，同时保留稳定 key 作为次要技术标识，并显示状态徽标（pass/warn/fail/error/skip）、detail、commandHint。key 与 commandHint 是契约/诊断信息，不参与翻译。
- 运行中可「取消」（走会话取消）；完成后显示耗时与「已取消」标记；未取消的结果自动加入报告历史。
- 空态提示 + 顶部命令提示（CommandHint）。

### 3.3 体检建议 opinion（Advisor）

- 展示 `healthResult.opinions`：每条建议按严重级别（critical/warn/info）着色卡片，含标题（i18n key）、正文、相关检查 key 列表。无结果时提示「先去运行体检」，可跳转 tree。

### 3.4 上不了网 offline（BasicView 集成区块）

- 上不了网是基础视角单页中的一个纵向区块，不再提供 captive/proxy/ipv6/mtu/egress/diff 子导航；摘要展示强制门户与代理/VPN，IPv6、MTU 和公网出口由下方各自可单项重测的面板显示结果，避免同一结果重复出现。
- 离线区块始终显示完整诊断说明。旧 sessionStorage 的 `offlineSub` 值不改变焦点，也不隐藏任何子面板。
- 「一键诊断」并发执行：检测强制门户（CaptivePortal）、公网 IP（egress）、代理/VPN 状态、IPv6 栈、路径 MTU。
- 路径 MTU 当前仅 macOS 实现；其他平台的 MTU 工具与跳转入口按能力矩阵禁用，一键诊断仍返回明确的 unsupported 子结果，不执行无效 DNS 解析。
- **一键诊断为 all-or-nothing**：并发执行 5 项并等待全部子请求 settled；任一子项失败时立即显示错误横幅 `networkProbe.errors.offlineFailed`，但保持 `loadingOffline`、禁用重试，直到其他子请求也结束，避免重试与旧请求重叠；已成功的子项结果**不落 store**。公网出口刷新与一键诊断共用 `loadingOffline`，不可并行；IPv6 / MTU 的独立面板保留各自 loading 和错误码，但与整组诊断互斥，因为它们共享结果槽位。独立检查运行时「一键诊断」禁用；一键诊断运行时基础视角中的 IPv6 / MTU 和测试页中的 MTU 均禁用。用例层也会拒绝冲突调用，避免其他入口或过期 UI 状态覆盖同一轮结果。
- 离线摘要和独立操作共享结果与运行状态；可逐项重测以下区块：
  - captive：状态（normal/captive/…）、detail、commandHint。
  - egress：公网 IP、来源、ASN/org、detail。
  - proxy：系统代理开关、VPN 接口列表、默认路由是否走隧道（warn）。`proxyStatusKnown=false` 时显示本地化“无法读取”，不把 IPC 默认值 `false` 呈现成“代理未开启”；`vpnInterfacesKnown=false` / `defaultRouteKnown=false` 时分别显示接口或路由状态未知，不把空列表 / `false` 呈现成“无 VPN”。健康树中 `proxy.system` 只反映代理读取，`vpn.tunnel` 只反映 VPN 接口和默认路由；VPN 读取失败且没有已知隧道证据时为 error，不得误报 pass。
  - ipv6：IPv6 栈状态、双栈对比 detail（`Ipv6Panel` 可单独运行）。
  - mtu：路径 MTU 状态/数值与本地化 unsupported 原因；MTU 面板在基础视角和 Test→MTU 均可单独运行，不支持平台不显示英文后端详情。

### 3.5 修复 fix（权限无关修复中心）

- 操作对象：网络服务下拉（自动优先 Wi-Fi → 有线 → 首个） + DNS 预设下拉（来自 defaults）。
- 操作按钮：**刷新 DNS**（DestructiveConfirm 一次确认）、**切换 DNS**（两步确认，第 2 步展示服务与目标 DNS 服务器）、**续租 DHCP**（两步确认）、**重置网络栈**（**TripleDestructiveConfirm 三步确认 + 手输 `RESET`**，最高危）、打开系统网络设置。
- DNS 切换、DHCP 续租与网络栈重置需加载网络服务列表；DNS 刷新不依赖服务。四个修复动作目前均只在 macOS 实现，能力矩阵为其他平台标记 unsupported、禁用对应操作并显示原因；服务相关操作全部不可用时不发起服务枚举。`resetNetworkStack` 在任何副作用前重新读取并校验服务白名单一次，随后复用该服务执行 DNS 刷新与 DHCP 续租，避免副作用后再次读取服务列表导致部分执行结果丢失。macOS DNS 刷新需缓存刷新与 mDNSResponder 通知两条命令都成功才标记成功；任一步失败仍尝试另一条，并在结果详情中保留部分执行反馈。服务列表、DNS 刷新、DNS 切换和 DHCP 命令均有墙钟上限和有界输出；服务列表输出截断会 fail-closed，变更命令超时会提示核验系统设置后再重试。结果卡将 action 和 ok 状态按当前语言本地化，保留 commandHint；原始 message 收在默认折叠的「系统反馈详情」中，便于排障且不把系统英文输出混入主界面。

**交互细节**：

- 服务下拉自动优先 Wi-Fi → 有线 → 首个（正则匹配 `wi-?fi|wlan` → `ethernet|usb` → 首项），未加载完成前按钮 `disabled`；DNS 预设默认选中第一项。
- **各修复按钮禁用条件细化**：刷新 DNS 需受支持且 `!loadingFix`；切换 DNS 需受支持、`service` 非空**且** DNS 预设非空（`servers.length===0` 时禁用，如预设列表为空）；续租 DHCP / 重置网络栈需受支持且 `service` 非空；「打开系统设置」无 loading 标志、任何时刻可点。服务/DNS 预设用**原生 `<select>`**（非 shadcn Select），label 以 `htmlFor` 关联。
- 所有修复按钮共用 `loadingFix` 全局禁用（防重入）；刷新 DNS / 切换 DNS / 续租 DHCP / 重置网络栈任一执行中，其余全部按钮禁用。
- 两步确认（切换 DNS / 续租 DHCP）：第 1 步「下一步」→ 延迟 320ms 弹第 2 步（确认服务与目标 DNS 服务器）；开始时固定服务 / DNS 预设快照，确认期间锁定对应控件与其他修复入口，任一步取消即中止；确认按钮在 `loadingFix` 时显示 loading。
- 三步确认（重置网络栈）：step1 后果说明 → step2 核对已固定的网络服务 → step3 勾选风险确认框 + 手输 `RESET` 才能点「立即重置」；确认期间服务选择、刷新、DNS 预设及其他修复入口均禁用；若已选服务被系统刷新移除，则关闭这次确认并要求用户重新选择、重新确认。后端忽略前端任何「已确认」标志，每次调用在副作用前重新校验服务白名单一次，并在本次执行内复用校验结果。重复调用不复用前次内存状态；DNS 刷新与 DHCP 续租部分失败时仍返回两步的结果详情。
- 结果卡：`lastResult.action + ok/failed` + message + commandHint；失败不弹 toast，直接在结果卡呈现（修复动作有确定性结果语义）。

### 3.6 报告 report

- 当前体检结果导出：**JSON**（整份 `HealthScanResult`）与 **Markdown**（含每个检查项与建议）浏览器下载；隐私提示文案。
- **历史快照**：最多保存最近 10 次未取消体检（localStorage `network-probe:report-history`），显示 sessionId/项数/耗时/建议数，可清空。整体占用限制 1 MiB；超限写入优先移除较早快照，单条超过上限时不纳入历史并保留已有快照。读取时校验 JSON 结构、每条快照字段/条目数量与检查项 key 唯一性；重复 session ID 只保留最新快照，损坏项跳过，整体损坏或超过 1 MiB 的存储按空历史处理。可选择两条不同快照，另一侧已选的快照在当前选择器中禁用；按 `HealthCheckItem.key` 对比各项状态，并标记状态变化、未变化以及仅存在于一侧的检查项；列表按最近到较早排序。对比不推导总体健康度，也不展示可能包含本机网络信息的详情文本；不足两条快照时提供前往一键体检的入口。
- **命令日志**：完整命令列表，可清空；报告页与侧栏使用同一二次确认，确认后清除整个会话日志。

## 4. 站点延迟（sites）L1

### 4.1 官方站点 official

- 官方站点包（`official` pack）卡片网格；每卡：站点名 + host、状态徽标（idle/ok/fail/running）、最近测试时间 + 延迟（HTTP TTFB 优先，回退 ICMP）、吞吐（HTTP 有界下载，≤1MiB/5s → `downloadMbps`）。
- Network Probe 的 HTTP 探测遵循操作系统代理配置（由 reqwest `system-proxy` 提供）；HTTP TTFB 反映应用实际网络路径，可能经过代理，不代表强制直连源站。
- 每张单测卡片的 hover/focus 命令提示显示 `startSitesProbe` 与实际目标；「测试全部」提示显示 official pack 参数。
- 顶部「测试全部」+ 统计（总数/OK/失败）；点击单卡只更新该站并保留其他卡片结果；在应用内切换 L1/L2 后返回仍显示本次会话结果；整包重测按该包目标清理旧结果并逐站更新。运行中可取消。
- 流式事件 `site-sample` 实时更新卡片；按 target 合并为最新样本，单卡重测更新该站的最新状态与时间；区域/自定义结果展示近 20 次延迟 Sparkline。

### 4.2 区域站点包 + 自定义 packs

- 区域包下拉（global / cn-friendly / dev / official，取自 defaults.sitePacks 除 official 外全部），运行整包。
- **自定义站点**：输入主机或 HTTP(S) URL（每项最多 2048 UTF-8 字节，前后端校验；超限即时显示双语错误并禁用添加）→「添加」→「运行自定义」；列表最多 24 项，按规范化 HTTP(S) URL 去重（主机大小写、默认路径斜杠不形成重复项）；达到上限后禁用添加并说明先移除一项；列表 chip 可逐个移除；持久化于 sessionStorage（`network-probe:custom-sites`），读取时丢弃超限项、去重并限制条目数。裸 IPv6 主机转换成 HTTPS URL 时须正确加方括号，URL scheme 按大小写不敏感处理。
- 结果表：每行 id、target · channel（degraded 标记）、Sparkline 迷你趋势线（近 20 次延迟）、ICMP/HTTP/吞吐或失败原因；流式刷新。样本 target 与最终 URL 只展示脱敏 origin：userinfo 不回显，非根路径、query、fragment 使用占位符；请求仍使用原始目标。

### 4.3 自定义站点持续监控（P5-2）

- 用户从自定义站点中选择 1–3 个目标后显式开始；监控会话固定这次选择，只探测已选目标，不因自定义站点总数更多而扩大范围。前端每次只为一个目标发起本地 IPC，以便在目标间响应隐藏 / 停止；沿用自定义站点的本地探测通道，不调用 Globalping 或自有 agent。HTTP URL 仅做 HTTP 状态/TTFB；host 按现有策略测 ICMP 与 HTTPS，优先 ICMP RTT、失败时用 HTTP TTFB。
- 立即采样，之后每 60 秒采样。一次最多 3 个目标，顺序探测、同一时刻最多 1 个监控周期；周期超过间隔时跳过重叠 tick。每个目标最多探测 15 秒，3 个目标的单周期上限为 45 秒；HTTP 请求自身复用 8 秒超时与只读取响应头的路径，不下载站点正文或吞吐数据。
- 可用性：连续 2 次失败通知一次；连续 2 次成功通知恢复一次。首次样本只建立状态，不通知。延迟：每个监控会话的前 5 个成功样本取中位数作为固定 baseline；阈值为 `max(1000 ms, 2 × baseline)`；连续 3 个样本超过阈值时通知一次，连续 3 个样本回到阈值内时通知恢复。停止并重启后重新校准。
- 仅在用户点击开始时检查 / 请求系统通知权限；拒绝或查询失败时不启动。每轮采样前再次检查授权，运行中撤权则停止监控并显示恢复说明。告警按状态转换去重，不重复发送仍处于 down / slow 的状态。
- 只在 Network Probe 站点面板挂载且应用窗口可见时调度；窗口隐藏时暂停新采样，重新可见后立即补一次并恢复 60 秒间隔。每个在途目标请求最多 15 秒；若窗口隐藏、页面卸载或应用退出，不再派发本周期的后续目标，并丢弃已在途请求的结果与通知。窗口重新可见时，若旧目标请求尚未结束，待其结束后立即启动新周期。上次检查时间按当前界面语言格式化。状态、baseline 和告警不持久化；选择的目标在监控期间锁定，停止后可修改。
- 通知标题与正文只显示站点主机名和状态/延迟，不含凭据、路径、查询参数或错误详情。监控样本不写命令日志，不作为长期历史保存；后台不常驻、不在窗口隐藏时继续采样。

**交互细节**：

- **输入护栏（前后端校验）**：Ping 次数为整数 `[1,20]`（默认 4），间隔 clamp `[100,5000]ms`；TCP 端口为整数 `[1,65535]`；Traceroute `maxTtl` 为整数 `[1,32]`（默认 20），`rounds` 为整数 `[1,10]`（默认 3）。renderer 对这些数值字段显示本地化内联错误并禁用无效提交，处理完成后恢复提交；Rust 保留整数 IPC 类型和边界夹限。端口扫描输入最多 2048 UTF-8 字节、最多 256 个不同端口，renderer 在字段旁显示本地化格式错误并禁用扫描，Rust IPC 仍独立校验并按端口去重；自定义站点每项最多 2048 UTF-8 字节、最多 24 个且按规范化 URL 去重，超限项不得进入 sessionStorage 或 IPC；非法 host / 空端口列表返回 `INVALID_INPUT` 并走错误横幅。
- **单工具防重入与取消反馈**：ping / dns / tcp / custom / traceroute / mtu / egress / speed 各自独立 loading，运行中不可重复触发；Ping 按包显示进度，运行期间锁定目标与次数，并可取消；health / 站点探测 / Ping / traceroute / speed / 端口扫描 / 抓包诊断 / ARP 发现等可取消任务共用取消按钮。请求发出后按钮禁用并显示本地化「正在取消…」，任务结束后显示取消结果；取消 IPC 失败时恢复按钮，允许重试。端口扫描若调用 nmap，取消会终止并回收其进程树；单条 nmap 命令有 35 秒上限。
- **单次操作重跑状态**：Ping / TCP / DNS / 自定义目标 / MTU，以及污染检测、WHOIS、DNSSEC、NAT、NTP、ARP 发现、局域网服务浏览、抓包诊断和多节点 DNS 的新请求开始时，先清除对应上次结果；Quick Fix 的 DNS 刷新、切换 DNS、DHCP 续租和重置网络栈也在每次操作开始时清除上一次修复结果；若本轮请求失败，展示本次错误，不将上次成功结果留作当前结果。离线完整诊断启动时同步清空 Captive、公网 IP、代理/VPN、IPv6 和 MTU 五项；公网 IP 单项刷新只清空旧 IP。
- **TCP 终态本地化**：`ok`、`refused`、`unreachable`、`dns_failed`、`timeout` 和 `error` 按当前语言显示；操作系统 `message` 收在默认折叠的「系统诊断详情」中，便于需要时查看原始诊断。
- **Ping 单包失败本地化**：IPC 返回稳定错误码（`timeout` / `permission_denied` / `network_error`），界面按当前语言显示，不直出 Rust/操作系统依赖的自由文本，避免中英文混排。
- **Ping 权限设置引导**：ICMP socket 初始化失败或逐包返回 `permission_denied` 时提示检查 Local Network 权限；macOS 按钮打开“系统设置 → 隐私与安全性”，用户再进入“本地网络”检查 Bench 授权。普通超时不显示权限设置按钮；打开失败时展示可重试的错误。
- **Ping 域名解析失败本地化**：解析失败使用稳定错误码 `DNS_RESOLUTION_FAILED`，显示独立的中英文提示，并归属 Ping 面板；与 ICMP socket 权限错误、超时或报文错误区分，不把依赖库或操作系统的原始错误直接显示在主界面。
- **自定义目标失败本地化**：HTTP 传输失败、HTTP 状态码失败和 TLS 握手失败均显示本地化状态；ICMP 未识别错误、HTTP 错误与 TLS 握手诊断只在默认折叠的系统详情中显示。
- **错误反馈归属**：错误横幅按错误 key 映射到所属 L1/L2 工具面板；取消失败按探测会话种类定位。基础视角是集成页，来自六个可见区块的错误都归属该页；切换 L1 或显式点击其他底栏锚点时清除已显示错误，手动滚动仅更新锚点并保留错误；晚到的旧请求错误仍按来源筛选，当前页已有可见错误时其他面板迟到的失败不得覆盖它；未分类的模块级初始化错误保持全局可见。
- **ping 全丢包提示**：`packetsReceived === 0` 时命令日志追加「可能需 Local Network 权限」提示（不静默）。
- **测速冷却与取消**：测速源失败/不可达时 `speedCooldownUntil = now + 30s`，期间「开始测速」禁用并倒计时提示（`测速源失败 — {{seconds}} 秒后可重试`），冷却结束自动恢复；取消成功不计入冷却。用户取消时应中止当前 ping / 下载 / 上传请求，不等待该请求的 45 秒超时。
- **测速传输上限**：下载最多计量 32 MiB；上传按测速源配置的上限发送，单次最多 8 MiB。下载响应按流计数，不把完整正文缓存到内存，达到上限后停止消费响应流。
- **测速冷却双重防护**：除按钮禁用外，`runSpeedTest` 用例入口 `if (speedCooldownUntil > now) return` 短路（连点/脚本调用也不触发）；冷却以 **500ms interval** 倒计时刷新；**源下拉在 `loading || coolingDown` 时同样 disabled**；结果卡 `unavailable`（`!ok && !cancelled && downloadMbps==null`）额外显示「测速源不可用」琥珀提示。
- **测速终态本地化**：不可用结果使用 `sourceUnavailable` 文案，取消结果使用 `cancelled` 标签；不直接显示 DTO 的后端 `message` 自由文本，避免与本地化状态重复或混用语言。
- **重新运行前状态复位（流式状态机）**：所有可重复探测（health / sites / traceroute / speed / ports / lan / pcap）每次开始时先 `resetXxxStreaming()` 清空上次流式数据 + `setActiveSessionId(null)`；speed 额外 `setSpeedSample(null)` / `setSpeedResult(null)`、ports 额外 `setPortScanResult(null)`，**新一次探测不留旧结果混淆**；`finally` 里统一 `setActiveSessionId(null)` 复位取消可用性。
- **流式采样去重**：`site-sample` / `port-sample` 按 target/port 合并去重（`upsert*`），单卡多次测试保留历史并绘制近 20 次 Sparkline；完成后对未取消的站点包结果保留已测卡片（取消提示「已完成的卡片结果会保留」）。

**交互细节**：

- **SecurityAuthGate**：未授权时 L1=security 显示琥珀色提示 + 「我确认 — 启用安全工具」按钮；点击后 `authorizeSecurity` 置位并持久化 localStorage；已授权显示「本机已授权使用安全工具。」+「撤销」；授权/撤销即时生效。未授权点击任何安全工具，use-case 直接 `setError(securityAuthRequired)` 且不发起 IPC。
- **端口扫描确认**：目标非内网（非私有/回环）或展开不同端口数 >64 时，点击「扫描端口」先弹 `DestructiveConfirmDialog`（展示目标 + 约 N 个端口 + 「仅扫描自有或已授权资产，当前为 TCP connect」），确认「仍然扫描」才执行；勾选范围内可免确认。端口语法、范围和大小在 renderer 显示本地化字段错误并阻止 IPC；Rust 对输入字节数、端口范围和去重后的数量再次校验，作为 IPC 安全边界。
- **局域网邻居发现空态**：按 `emptyReason` 区分本地网络权限拒绝（引导打开隐私设置）、无可用 IPv4 接口（引导打开网络设置）、扫描范围超出 `/24`（只读缓存并说明跳过主动探测）、客户端隔离和安静网络；前端显示对应本地化原因，不直接展示后端自由文本 `message`，避免中英文混排和重复原因。
- **局域网服务浏览**：`mdns-sd` 负责 DNS-SD 服务类型发现与 PTR/SRV/TXT 解析；SSDP 仅解析收到的响应，不请求 `LOCATION`。准备、mDNS、SSDP 阶段通过 session-scoped 进度事件显示实际唯一服务数，取消保留已完成项；mDNS 服务类型上限 64，结果上限 256，错误行不计入发现数。
- macOS Local Network 权限拒绝是否能由当前 mDNS dependency 与安静网络区分，必须使用隔离 QA bundle 在临时用户下实测；未验证前不把专用拒绝态标为已完成。

Globalping HTTP 结果只向 renderer 返回脱敏后的 URL 目标与命令提示；公共 API 的原始输出不回传，避免将可能回显的私有路径带入详情或报告，状态码与结构化时序仍保留。Ping 探点的原始诊断输出仍可在折叠详情中查看。

Globalping 创建和轮询的成功 JSON 响应均限制为解压后 512 KiB：根据 `Content-Length` 提前拒绝，并在流式读取期间再次执行实际字节上限。超限或 JSON 无效仅将该远端请求记为失败，保留已有本机 DNS 和已完成探点；`429` / `304` 继续按状态码与响应头处理，不解析响应体。

ARP 主机发现先显示接口 / 邻居缓存准备状态，不提供百分比；确定探测地址后按已完成 host probe / 目标数显示真实进度，并按唯一 IP 更新实时邻居数。取消时保留已完成探测结果和缓存邻居，不把中止任务计为完成。局域网服务发现按 mDNS / SSDP 阶段和唯一服务数实时更新进度，取消保留已发现项；静态实现及自动化回归已完成，Local Network / TCC 与常见设备发现仍待隔离 macOS 真机验收。

## 8. 能力包（D-017 packs）

- **能力包**：`adv-scanner`（SYN 扫描）、`pcap-diag`（诊断抓包）、`priv-helper`（特权 helper）。内置 manifest（packId / version / hash / 签名来源）。
- PackInstallDialog：pack 列表（version / sizeMB / status / markerOnly 提示 / 描述），安装 / 卸载 / 刷新；安装走后端（**禁止前端传 URL**，marker + hash 校验，测试通道可强制 hash-fail）；进度事件 `pack-progress` 实时显示 `packId phase bytes/totalBytes`。操作结果用本地化状态显示，失败提供 alert，原始后端诊断默认收起；对话框关闭或新开时清除旧结果。
- 安装/卸载后自动刷新 capabilities 与 packs 列表；capabilities 中 `tools.<key>` 可反映 `missing_pack`（缺能力包时面板显示缺失提示并可跳转安装）。

**交互细节**：

- pack 列表为单选项列表（点击选中高亮），选中后右侧描述区展示 pack 描述 + Gatekeeper 说明；安装/卸载按钮带 CommandHint 包裹（hover 显示真实命令）。
- **focusPackId 自动聚焦**：从 pcap 面板「管理能力包」入口进入时自动选中 `pcap-diag`、从端口/ARP 面板进入时自动选中 `adv-scanner`（`focusPackId → setSelected`）；pack 列表为空时右侧显示 `packs.empty` 占位。
- `busy` 为真时**全部按钮禁用**（刷新/安装/卸载/测试哈希失败），安装按钮文案切为「安装中…」；进度文本 `packId phase bytes/totalBytes` 实时刷新，安装完成/失败后清除。
- **能力包刷新防重入**：`refreshCapabilityPacks` 用例使用 `loadingCapabilityPacks` single-flight，页面将该状态与安装 / 卸载的 `packsBusy` 合并传给 PackInstallDialog；对话框所有操作按钮在忙碌时禁用。刷新任一来源失败会立即显示错误，但等另一来源结束后才释放 loading，避免重复发起并发读取。
- 已安装 pack 显示「卸载」（destructive 样式）；未安装显示「安装」；`markerOnly`（制品未发布）显示标记提示。
- 「测试哈希失败」按钮（验证通道）仅用于开发验证：开发构建默认可见，普通发布构建隐藏；显式 QA 构建可通过 `VITE_BENCH_ENABLE_PACK_VERIFY_TEST=1` 开启。安装强制返回 hash 不匹配并写入命令日志，不实际安装。

## 10. 技术实现要点

- **架构分层**（Feature-sliced）：`page.tsx`（装配）→ `components/`（面板 UI，`ProbePanelShell` 统一工具栏/内容壳）→ `hooks/useNetworkProbeController`（store↔use-cases 桥接，逐项 selector）→ `services/network-probe.use-cases.ts`（业务编排、事件订阅、防重入、取消幂等）→ `services/network-probe.repository.ts`（IPC 适配）→ `@/lib/tauri/commands/network-probe`。
- **store**（zustand）：单一 feature store，保存全部结果/loading/error/导航/安全授权/报告历史/命令日志/会话状态；持久化仅 nav（sessionStorage）、securityAuthorized 与 reportHistory（localStorage）。
- **IPC 契约**：`src/lib/tauri/contracts.ts` + `src-tauri/src/net_probe/commands.rs` 双边集中维护；全部命令返回 `AppResult<T>`。
- **长任务**：events 流式（`network-probe:health-item` / `traceroute-hop` / `site-sample` / `ping-sample` / `speed-sample` / `port-sample` / `pack-progress` / `scan-session` / `lan-services-progress`）；会话取消统一 `network-probe-cancel-scan(sessionId)`，**同一会话只允许发一次取消（幂等）**，新会话重置取消标记（有单测 `cancel-idempotency.test.ts`）。
- **capabilities 能力声明**：后端 `build_capabilities` 返回 platform / privilegeLevel / tools 状态（supported/partial/degraded/unsupported/missing_pack）/ externalTools（如 nmap）；前端 `toolEnabled` 依此控制按钮可用性与降级提示。
- **defaults 目录**：`get_network_probe_defaults` 返回 DNS 预设、站点包、探测目标、强制门户、公网 IP API、MTU 目标等默认资源。顶栏「默认资源」提供六类名单的表单编辑；按类保存只合并当前覆盖，避免覆盖其他类别并保留后续新增的内置类别；恢复全部内置名单需二次确认。六类覆盖均由后端消费：站点 / DNS 快捷修复读取当前目录；健康检查按 `pub-ip-v4`、`pub-name` 优先并在失败后依序尝试同类型目标，公网出口按 API 顺序故障转移，强制门户探测使用整组配置，DNS 名称检查使用 `dns-resolve-name`，MTU 健康检查使用首个 MTU 目标，独立 MTU 面板提供预设选择和手动输入。后端将覆盖限制为 256 KiB；DNS / MTU 目标每类最多 128 项，连通目标每种类型最多 3 项，强制门户与公网 IP API 各最多 3 项，站点包最多 32 个且每包最多 128 项。禁止空列表 / 空站点包，校验标识、唯一性、IP/主机、HTTP(S) URL 和响应格式，再以原子替换方式串行写入；公网 IP API 仅允许 HTTPS，每个候选 API 只请求一次，不先探测再重复请求，响应体限制为 16 KiB，按声明格式解析和验证 IP，最多跟随 3 次 HTTPS 重定向且不允许降级到 HTTP。当前公网 IP 查询不缓存。DNS 切换只接受当前默认资源目录中的地址，因此自定义 DNS 预设可直接用于 Quick Fix。
- **面板复用**：offline 内的 ipv6/mtu/egress 复用同一 `Ipv6Panel`/`MtuPanel`/`EgressPanel`（`dualFrom` 区分来源），避免双入口冲突。
- **测速护栏**：LibreSpeed 硬上限 32/8 MB、失败 30s 冷却。
- **体检健壮性**：VPN/utun 默认路由无 gateway 行不误报；代理读取状态只决定 `proxy.system`，VPN 接口 / 默认路由只决定 `vpn.tunnel`；VPN 查询失败且无已知隧道证据时为 error，不以空列表报 pass。识别 DNS Fake-IP（198.18/15）与本地系统代理；`reach.public_name` 在 Fake-IP 下跳过 ICMP。

## 12. 边界与限制

- **硬红线（法律/合规）**：不实现主动攻击能力——ARP 欺骗**攻击** / MITM 流量**注入** / **DoS** / 密码**爆破** 一律不构建；仅提供对应检测/防御（`detectArpSpoofing` 只读 MAC 冲突提示、`checkSsl.mitmSuspected`、暴露面评估）。
- 平台：macOS 主路径；Windows 能力降级/隐藏；Linux 非目标。权限不足（Local Network / TCC）给出稳定错误 + 打开系统设置入口，不静默失败。
- 高危修复（重置网络栈）三次确认 + 手输 `RESET`；端口扫描非内网/超 64 端口二次确认；安全 Tab 需显式授权。
- 测速/探测均有冷却与取消；长任务可取消，取消幂等。
- 命令日志与报告导出可能含本机网络信息，报告导出带隐私提示；数据不落盘（除 reportHistory 最近 10 条）。
- 能力包为 marker + hash 校验安装路径（sidecar 下载路径已预留），前端禁止传下载 URL。

## 13. 异常处理

### 13.1 错误码 → 前端提示映射

后端统一返回 `{ code, message }`（`src-tauri/src/error.rs` AppError），前端 `parseCommandError`/`getErrorMessage` 解析；use-case 统一 `setError({ key: "networkProbe.errors.<tool>Failed", fallback })`，顶部错误横幅展示本地化文案。

| 错误码                                                   | 场景                                                                                                                                         | 前端行为/提示                                                                        |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `INTERNAL` / `TASK_FAILED`                               | 内部错误 / `spawn_blocking` JoinError                                                                                                        | 错误横幅显示 `networkProbe.errors.*Failed` + 后端 message                            |
| `INVALID_INPUT`                                          | 非法 host、空端口列表、>256 端口、非法 DNS IP、DNS 服务不在白名单、DNS 服务器 >4；探测目标长度 >2048、URL scheme 非 http/https（`input.rs`） | 错误横幅展示，不重试；修正输入后重试                                                 |
| `NOT_FOUND`                                              | 目标资源不存在                                                                                                                               | 错误横幅                                                                             |
| `UNSUPPORTED`                                            | Windows/Linux 上 macOS-only 操作（网络服务枚举、修复、防火墙状态等）                                                                         | 面板降级/隐藏，或显示「仅 macOS 实现」提示                                           |
| `IO_ERROR` / `FORBIDDEN_PATH`                            | networksetup 等外部命令失败、路径越界                                                                                                        | 错误横幅 + 后端 message                                                              |
| `ICMP_UNAVAILABLE`                                       | ICMP socket 打开失败（ping.rs）                                                                                                              | 提示「可能需 Local Network 权限」，引导打开系统设置；ping 全丢包时命令日志追加同提示 |
| `DNS_LOOKUP_FAILED` / `DNS_CONFIG`                       | DNS 解析失败 / 解析器配置读取失败                                                                                                            | 错误横幅 `networkProbe.errors.dnsFailed`                                             |
| `NETWORKSETUP_FAILED`                                    | `networksetup -listallnetworkservices` 失败                                                                                                  | 错误横幅 `networkProbe.errors.servicesFailed`                                        |
| `NTP_BIND/DNS/SEND/RECV/TIMEOUT/SHORT`                   | NTP 探测各阶段失败                                                                                                                           | 错误横幅 `networkProbe.errors.ntpFailed`                                             |
| `NAT_BIND/DNS/SEND/RECV/TIMEOUT`                         | NAT/STUN 探测各阶段失败                                                                                                                      | 错误横幅 `networkProbe.errors.natFailed`                                             |
| `SPEED_CLIENT`                                           | 测速源请求失败                                                                                                                               | 进入 30s 冷却 + 错误横幅 `networkProbe.errors.speedFailed`                           |
| `GP_CLIENT` / `GP_PARSE`                                 | Globalping 节点请求/解析失败                                                                                                                 | 错误横幅 `networkProbe.errors.multiNodeFailed`                                       |
| `WHOIS_CLIENT`                                           | RDAP 查询失败                                                                                                                                | 错误横幅 `networkProbe.errors.whoisFailed`                                           |
| `MDNS_START/BROWSE` / `SSDP_BIND/BROADCAST/SEND/RECEIVE` | mDNS daemon、服务浏览或 SSDP 收发失败                                                                                                        | 协议级错误行默认折叠系统详情；可继续执行另一协议                                     |
| `TRACEROUTE_BUILD` / `TRACEROUTE_RUN`                    | traceroute 构建/运行失败                                                                                                                     | 错误横幅 `networkProbe.errors.tracerouteFailed`                                      |
| `PACK_URL_INSECURE`                                      | 包下载 URL 非 https（仅后端 manifest）                                                                                                       | 错误横幅 `networkProbe.errors.packsFailed`（正常不可达，防篡改）                     |
| `PACK_CLIENT` / `PACK_DOWNLOAD`                          | 包下载网络失败（120s 超时）                                                                                                                  | 错误横幅 `networkProbe.errors.packsFailed`；可刷新后重试                             |
| `PACK_HASH_MISMATCH`                                     | SHA-256 校验失败（marker-only / 下载损坏）                                                                                                   | 错误横幅 `networkProbe.errors.packsFailed`，二进制不安装                             |
| 前端 `securityAuthRequired`                              | 安全 Tab 未授权调用                                                                                                                          | 错误横幅「请先确认安全 Tab 授权声明。」，不发起 IPC                                  |

### 13.2 常见失败场景与行为

| 场景                                     | 行为/提示                                                         | 恢复/降级                                                                                              |
| ---------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 网络断开/超时                            | 各探测命令返回对应错误码 → 错误横幅                               | 重试；`caps.localNetworkHint` 提示「全部探测丢失可能是权限/防火墙/真实断网，不要当唯一结论」           |
| 权限拒绝（Local Network / TCC / 无特权） | Ping `permission_denied`、邻居发现 `emptyPermission`、pcap 无特权 | 邻居发现停止剩余 TCP 探测并保留 ARP 缓存；pcap 降级到 tcpdump 计数；给出对应隐私或网络设置入口，不静默 |
| 平台不支持（Windows/Linux）              | `UNSUPPORTED` 或能力矩阵 `unsupported`                            | 面板隐藏/禁用 + toolDisabled 提示；firewall 返回 status=unsupported + detail                           |
| 能力包缺失                               | `tools.<key> = missing_pack`                                      | 面板禁用 + 「管理能力包」入口跳转安装；安装后自动刷新                                                  |
| 外部工具缺失（如 nmap）                  | externalTools 反映                                                | 端口扫描降级为 TCP connect（degraded），提示安装 adv-scanner/nmap 可启用 SYN                           |
| 测速源不可达                             | `!result.ok && !cancelled`                                        | 30s 冷却倒计时禁用，可换源；取消成功不计冷却                                                           |
| 取消命令本身失败                         | `cancelFailed`                                                    | 错误横幅提示；清除当前会话的取消请求标记并恢复按钮以便重试，不影响较新的会话标记                       |
| 一键诊断部分子项失败                     | 首项失败立即反馈；等待全部子请求结束后恢复重试                    | `offlineFailed` 错误横幅、已成功子项不落 store；可改用各子面板单独运行定位                             |

### 13.3 幂等 / 取消 / 并发保护

- **会话取消幂等（前后端双保险）**：前端 `cancelRequestedSessionId` 保证同一 `sessionId` 只发一次 `cancelScan`；按钮随后禁用并显示「正在取消…」。取消 IPC 失败只清除与失败请求匹配的标记，恢复该会话的重试入口，不会覆盖较新会话的请求。后端 `session.rs` 以 `HashSet` 记录已取消 id，重复取消为 no-op 成功。新会话（新 sessionId）自动重置取消标记（有单测 `cancel-idempotency.test.ts`）。
- **站点探测可中断当前请求**：取消会丢弃正在等待的 HTTP/ICMP 探测 future，保留已完成样本并返回 `cancelled=true`；若没有已完成样本，面板仍显示「已取消」状态。
- **事件监听清理**：所有流式长任务在 `finally` 中 `unlisten()` 全部事件订阅（health-item / site-sample / traceroute-hop / ping-sample / speed-sample / port-sample / scan-session / pack-progress），避免泄漏与跨会话串扰。
- **单工具防重入**：每个 use-case 入口 `if (store.loadingX) return`；同一工具不可并发，不同工具可并行（store 每工具独立 loading）。
- **离线诊断结果槽互斥**：`checkIpv6Stack`、`probePathMtu` 与 `runOfflineDiagnostics` 共写 IPv6 / MTU 结果槽；一键诊断启动时若单项检查仍在运行则拒绝执行，反之亦然。基础视角和测试页的按钮同步禁用，use-case 入口保留最终保护；公网出口与整组诊断继续通过共享 `loadingOffline` single-flight。一键诊断首项失败立即显示反馈，但要等其他子请求收敛后再释放 loading，避免重试并发执行。
- **修复幂等**：后端每次执行前重新校验服务白名单（忽略前端「已确认」标志）；刷新 DNS 对 `dscacheutil`/`killall` 分别报告成功/失败，不把权限失败当成功。
- **single-flight 式刷新**：刷新概览（`loadingSummary`）、能力包（`loadingCapabilityPacks`）、节点（`loadingNodes`）在用例内以 loading 标志防重复触发；概览和能力包刷新即使任一来源先失败，也要等其他读取结束再解锁，同时立即显示错误。
- **agent 注册表并发安全**：`addAgent` / `removeAgent` / `refreshProbeNodes` 共用 `loadingNodes` 防重入和控件禁用态；后端 registry 读改写由进程内互斥锁串行化，并使用 `persistence::atomic_write` 替换文件。重复的「同标签 + 同规范化 HTTPS/WSS URL」注册返回已有节点，不创建重复记录。刷新以最多 8 个并发、每端点 5 秒时限重新检查 HTTPS 2xx 或 WSS Ping/Pong；registry 读取失败向 IPC 传播，不以空列表伪装刷新成功。agent 当前只报告可达性，未协商或声明远程探测能力，实际执行仍待 C2-3。
- **Quick Fix 服务与系统设置操作**：`loadNetworkServices` 和 `openSystemNetworkSettings` 均由 use-case loading 状态 single-flight；服务列表加载期间禁用选择与刷新按钮，空列表显示明确提示并保留重试入口。刷新失败保留已加载服务列表，同时显示错误横幅；成功刷新后若先前选择的服务已消失，清除该选择并禁用依赖服务的修复动作；即使还有其他服务，也要求用户明确重新选择，避免把修复静默切到另一块网卡。打开系统设置期间按钮禁用并显示进行中状态，避免重复派发打开请求。

### 13.4 数据与安全

- 报告导出（JSON/Markdown）含公网 IP、Wi-Fi SSID、hosts 异常等，导出前展示隐私提示；reportHistory 仅保留最近 10 条（localStorage），清空需确认。
- 能力包安装路径：前端禁止提交下载 URL；仅后端 manifest 的 https URL + SHA-256 校验；`PACK_HASH_MISMATCH` 时二进制不落盘。
- `saveDefaultsOverride`/`resetDefaults` 失败 → `networkProbe.errors.defaultsFailed`；默认资源损坏时重置即可恢复内置值。
