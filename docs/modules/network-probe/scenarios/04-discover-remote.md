## S-DIS-01 · 看看局域网有谁

### 背景

家庭用户想看当前 Wi‑Fi 下有哪些设备；可能未装 `adv-scanner`。

### 前置

- 用户有权检查所选本地网络
- 界面提前说明会对当前 IPv4 子网发起 TCP 80/443/22 连接探测；最多 `/24`，不发送原始 ARP 请求
- 扫描网段由系统默认接口 / 网关 / 实际前缀识别；VPN 默认路由下不可唯一确认 LAN 时应跳过扫描

### 步骤

1. L1「发现」→「局域网邻居」，先阅读按钮旁说明：TCP 80/443/22、最多 `/24`、不发送原始 ARP、只扫描获授权网络
2. 点击「扫描当前子网」后观察准备提示；网段确定并开始探测后，进度条分母与真实目标 host 数一致，已检查数只随完成的 host probe 增长
3. 检查实时邻居数按唯一 IP 计数，包含缓存与 TCP 响应；对缓存中已有的 IP 再收到 TCP 响应时不重复计数
4. 观察主机表（IP/MAC/接口/来源）；结果中的 CIDR 与发现模式说明实际选定范围
5. 空结果时切换中英文，确认只显示与 `emptyReason` 对应的本地化原因，不显示后端英文原文或内部 mode 枚举
6. 在真实 `/24` 私网确认仅发起 80/443/22 TCP connect 探测；当前实现不发送原始 ARP 请求
7. 使用大于 `/24` 的受控网段时确认跳过主动探测、仅显示同网段系统缓存并解释范围限制
8. 使用非 RFC 1918 地址（包括公网或链路本地）时确认跳过主动探测并显示准确范围说明
9. 使用私有 `/32` 主机路由时确认显示无其他主机可探测，而不是“安静网络”
10. 用在同一子网配置多个 IPv4 地址的接口确认这些地址不会作为发现到的远端邻居返回
11. 用含隧道接口的设备确认不把 VPN/utun 地址作为 LAN 网段；若无法唯一识别物理私网则不扫描且不显示无法归属的邻居缓存
12. 在 Windows 11 真机确认系统邻居表使用 `GetIpNetTable2(AF_INET)` 读取，MAC 和 `InterfaceIndex` 对应正确；空表不误判为读取失败，API 错误则继续 TCP-only 探测
13. 扫描期间取消且已有缓存或 TCP 结果时，确认只保留已经完成的探测结果、已检查数不计入被中止任务，并明确显示已取消
14. 在接口识别 / 系统缓存预检期间点击取消，并在无接口或范围跳过条件下检查返回：均显示取消状态；预检错误路径结束后会话可正常再次运行

### 期望

- 使用系统接口元数据和实际前缀，扫描范围不会静默缩小或扩大；仅含其他地址的 RFC 1918 私网 `/24` 或更小可主动探测，私有 `/32` 显示无主机可探测，所有本机地址均从探测目标排除，速率硬顶、可取消
- 点击前的常驻说明告知连接探测端口与范围；仅允许探测自有或获准网络；公网及其他非私网范围默认跳过，不提供未经确认的全网扫描
- 空结果文案按 `emptyReason` 区分权限/客户端隔离/真静网；双语 UI 不直接展示后端 `message`
- macOS 与 Windows 读取系统邻居缓存；读取失败时如实标记 TCP-only 并继续允许的主动探测，Windows 真机验收未完成前不声明运行时通过
- 扫描取消后即使保留了部分邻居列表，也显示已取消状态，不把部分结果伪装成完整扫描
- 扫描进度基于实际 host probe 完成数，预检阶段不伪造百分比；实时邻居数按唯一 IP 计算
- 取消在接口 / 缓存预检阶段或主动连接阶段均有效；无接口、范围跳过等早退结果保留对应原因并标记已取消，会话在错误与正常早退时都会清理
- 本地网络权限被拒时立即停止剩余网段连接，并引导用户检查 Local Network 设置
- **无** ARP 攻击/投毒入口
- 本地网络权限未开时有设置引导

## S-DIS-02 · 浏览 mDNS / SSDP 服务

### 背景

想找打印机、NAS、智能设备的发现服务。

### 步骤

1. 「局域网服务」开始浏览，确认准备中、mDNS 与 SSDP 阶段按顺序显示
2. 查看 mDNS 服务类型/端口/TXT；SSDP 设备名与 LOCATION，并确认列表更新时实时唯一服务数增加
3. 在 mDNS 阶段与 SSDP 阶段分别取消，确认能在短时间内结束、保留已发现结果；没有结果时显示“已取消”而不是“没有响应”
4. 对同一 USN 的重复 SSDP 响应和同一 DNS-SD fullname 的重复事件确认只计一次
5. 确认 UI **不能**一键调用 UPnP 端口映射等写操作，且不会对 LOCATION 发起 HTTP 请求
6. 在临时 macOS 用户 / 隔离 QA bundle 中分别允许和拒绝 Local Network 权限，确认系统提示、重试和结果文案；静态构建不代表这项通过（静态实现 / 自动化已完成，真机未验收）

### 期望

- 只读发现；mDNS 按服务 fullname、SSDP 按 USN 去重；没有 USN 时使用 IP/ST/LOCATION 组合
- mDNS 与 SSDP 各自有硬超时；取消后返回已完成结果，事件按 session ID 过滤并释放监听器
- 最多浏览 64 种 mDNS 服务类型并返回 256 项；TXT / 系统详情受长度限制，不获取 LOCATION
- 进度计数只包括唯一、成功解析的服务；协议错误不计作发现服务

## S-DIS-03 · NAT 类型 + NTP 偏移

### 背景

排查 P2P/通话问题时需要 NAT 类型；同时怀疑系统时间不准导致 TLS 异常。

### 步骤

1. 「NAT 类型」跑 STUN（多服务器）
2. 「NTP 时间」看 offset；超出阈值告警
3. 确认本模块**不**擅自修改系统时钟

### 期望

- NAT 分类有产品文案；UDP 阻断要诚实
- NTP 多源中位数；与「公网出口」面板职责不混（出口≠NAT）

## S-DIS-04 · 多地对比同一域名 DNS

### 背景

本机解析正常，但怀疑区域污染；用 Globalping 多探点对比。Globalping 会公开保存测量数据；只提交已获准公开的 DNS 名称。产品会拒绝 IP 字面值、单标签名和已知本地 / 特殊用途名称，但无法仅凭域名格式判断自定义 split-horizon 私有域名。

### 前置

- Post-C；可匿名额度或已配置 token
- `listProbeNodes` 含 local + 若干 `remote-proxy`

### 步骤

1. 输入目标域名并运行 DNS 对比
2. 运行期间确认本机结果先出现；Globalping 已完成探点逐步补入，尚未完成的探点不误显示为失败
3. 并排查看本机、Globalping 世界 / 美国 / 欧洲探点的答案
4. 检查节点、token 和 agent 管理默认折叠在操作区；已有结果优先显示在独立滚动区，不被固定工具栏挤出首屏
5. 额度用尽时出现可理解错误（非空成功）
6. 让单个 Globalping API 请求悬挂，确认单请求超时后本机结果仍保留
7. 让 Globalping 快速返回 `in-progress`，确认远端总轮询在 20 秒截止且不会再多睡一个轮询间隔
8. 展开可选 token 设置，显式查询钥匙串状态、保存 token 后清空密码框，再移除 token 并确认状态更新
9. 确认 token 不进入应用持久化、命令日志或可见输入值；DNS 对比读取 token 时如系统要求钥匙串授权，应由系统提示明确告知
10. 模拟钥匙串读取失败，确认保留本机 DNS 结果且不向 Globalping 发出请求
11. 使用失效 token 模拟 HTTP 401/403，确认只将 Globalping 节点标记为授权失败，本机结果仍可见
12. 请求期间点击「取消」，确认本机停止等待并保留已收到的答案
13. 输入保留域名 `bench-qa-no-such-host.invalid`，确认没有 DNS 答案的探点显示无答案状态，不显示成功
14. 输入 `router.home.arpa`、`printer.local`、单标签 `router` 或 IP 字面值，确认在创建会话及发出 DNS 请求前拒绝目标；确认公开数据提示仍提醒不要提交自定义私有域名

### 期望

- 结果按 local 和每个 Globalping 探点分别展示
- DNS 对比要求域名输入，拒绝 IP 字面值、单标签名和已知本地 / IANA 特殊用途名称；该语法检查不能识别所有自定义私有区，持续显示的公开数据提示须明确让用户确认域名已获准公开
- 摘要显示探点结果行数（包括失败行）；DNS 答案数量只指各行实际返回的记录，不用它解释行数
- 远端失败不阻断整表
- 交互模式请求启用 `inProgressUpdates`；本机 DNS 完成后立即发布一次部分结果，随后只发布已结束的远端探点，并按 session ID 隔离事件；剩余探点运行时 UI 明示当前结果为部分结果
- 本机 DNS 最多等待 5 秒；单个 Globalping API 请求最多等待 8 秒，整个测量最多轮询 20 秒，每次状态请求间隔至少 700 ms
- 任何非 `in-progress` 状态均按终态处理；超时以失败探点显示，不能把未完成测量伪装成成功
- 只有状态为 `finished` 且至少返回一条 DNS 答案的探点才显示成功；已完成但无答案时显示本地化「无 DNS 答案」，测量失败 / 离线状态显示测量失败
- 本机 DNS 请求失败与 5 秒超时分别显示本机错误说明；Globalping 请求失败与 20 秒总超时显示远端错误说明，不得混淆探点归属
- 「取消」停止本机请求与轮询；已提交的 Globalping 测量可能继续运行，界面须说明这一点
- token 为可选项；未配置时使用匿名额度。token 由 Rust 后端写入系统钥匙串，只用于固定 HTTPS API `api.globalping.io` 的 Authorization 请求头，不得写入 renderer 持久化或命令日志
- 钥匙串状态检查、保存和移除都由用户显式触发；钥匙串读取失败不得阻断或丢弃本机结果，且不得发起 Globalping 请求；401/403 使用独立授权错误状态
- 配额、超时、请求失败和探点无答案使用本地化状态；若 Globalping 返回 `429` 响应头，则分别显示限速积分、可用 credits 与相对重置秒数（仅展示实际提供的字段）；原始诊断细节默认折叠
- 命令日志标注 `via globalping`
- **不**要求本机 Adv pack（远程零重库）

### 档位

## S-DIS-05 · 添加自有 agent 节点

### 背景

团队在机房放了自有 probe agent，想从笔记本确认其安全连接与在线状态。

### 步骤

1. 手动添加 HTTPS/WSS agent endpoint
2. `listProbeNodes` 出现 `remote-agent`
3. 列表显示 agent 的 TLS 健康检查状态
4. 负向：HTTP 明文、URL 凭据、查询参数和片段被拒
5. `rejectAgentAction('shell')` 拒绝任意 shell 动作
6. 注册表达到 256 条后新增一个新 endpoint，确认在健康检查前显示上限错误；同标签 + 同 URL 的重复登记仍幂等
7. 在隔离 QA 数据中分别构造超过 256 条和超过 1 MiB 的 `agents.json`，刷新节点并检查全局可见的双语恢复提示、重试入口，以及不会把异常数据伪装成空节点列表
8. 备份并修复隔离注册表后点击重试，确认默认节点与合法 agent 能恢复加载
9. 启动时让 `listProbeNodes` 暂不返回，在该请求期间完成 agent 新增或移除，再释放启动时取得的旧节点快照；确认旧快照不会覆盖刚完成的节点变更

### 期望

- HTTPS/WSS；HMAC 或 mTLS；限速 429 映射 `AppError`
- 禁止明文；禁止局域网自动扩散发现 agent
- SSRF：直接填写或解析到已知云元数据 IP / 主机名时拒绝保存并显示本地化原因；其他手动填写的内网 agent 仍允许
- 注册表最多 256 条 / 1 MiB；加载使用有界读取，新增在网络检查前预检容量且并发写入时再次验证；超限文件 fail-closed 并提供中英文恢复说明 / 重试，不静默截断或清空用户数据

当前注册健康检查契约：HTTPS `GET /v1/health` 返回 2xx；WSS 在 `/v1/health` 完成 TLS WebSocket 升级并响应 Ping/Pong。两种传输都使用系统证书根，HTTPS 不跟随重定向；直接指向 `169.254.169.254`、AWS IPv6 IMDS `[fd00:ec2::254]`、Google Cloud IPv6 metadata `[fd20:ce::254]`、`metadata`、`metadata.goog`、`metadata.google.internal` 及其子域的 endpoint 会在注册和健康检查前被拒绝。每次健康检查还会解析主机名并拒绝任何命中上述元数据 IP 的结果，再将 HTTPS / WSS 连接固定到已检查地址以防别名或 DNS 重绑定；agent 健康检查直连且不使用系统代理，其他手动添加的内网端点保持可用。单端点最多等待 5 秒，列表刷新最多并发 8 个检查。凭证鉴权、429 语义和远程探测执行仍待 C2-3。

当前 UI 明示 agent 仅检查可达性；remote-agent 不参与 DNS / Ping / HTTP 探测，也不宣称相关能力。远程探测执行和凭证鉴权未完成前，不把 agent 显示为可用于远端对比的结果节点。

## S-DIS-06 · Globalping 多地 Ping / HTTP

### 背景

本机网络正常，但想比较不同地区到同一公网目标的延迟，或检查公开站点的响应状态与连接时序。

### 前置

- 使用发现 → 多节点面板；Globalping token 可选，未配置时使用匿名额度
- Globalping 会公开保存测量目标、选项和结果；不得提交账号凭据、私密 URL 或机密数据
- 仅支持公网目标；自有 agent 当前只报告 HTTPS/WSS 健康状态，不运行远程探测

### 步骤

1. 切换到 Ping，输入公开主机名或公网 IP，启动测量
2. 查看世界 / 美国 / 欧洲探点的完成状态、解析地址、RTT 与丢包率
3. 切换到 HTTP，输入绝对 HTTP(S) URL，选择 GET 或 HEAD 后启动测量
4. 查看每个探点的 HTTP 状态码和 DNS、TCP、TLS、首字节、下载时序；4xx / 5xx 仍明确显示服务端返回的状态码
5. 尝试提交私网 / 保留 IP、`.local` 主机、含 URL 凭据、查询串、片段的 URL 或 POST 方法，确认在本机拒绝且不发起 Globalping 请求
6. 测量运行期间点击取消，确认本机停止轮询并保留已收到的探点结果；提示已提交的远端测量可能继续
7. 使用无效 token，确认 Ping / HTTP 同样正确使用钥匙串配置并显示授权失败
8. 确认节点管理、token 和 agent 设置折叠在设置区，测量结果视口保持可读
9. 模拟 Globalping 成功响应的 JSON 超过 512 KiB（含分块传输），确认该远端结果标记为请求失败、不会继续累计大响应，且本机 DNS 和其他探点结果保留

### 期望

- Ping 只接受裸公网主机名 / IP；HTTP 只接受绝对 HTTP(S) URL 与 GET / HEAD，不发送 URL 凭据、查询串、片段或自定义请求头
- Globalping 测量数据公开可见的提示在操作区持续显示；产品不支持把私有目标或机密数据提交给公共探点
- 仅展示实际完成的探点；结果包含 Ping RTT / 丢包或 HTTP 状态 / 分段时序，并用中英文标签呈现
- HTTP 的结果目标和命令提示仅显示脱敏 URL origin；不向 renderer 回传可能回显私有路径的原始 HTTP 输出，结构化状态码和时序仍可用
- 固定节点清单仅含 world、US、Europe；IPC 拒绝重复、未知或超过三个的 Globalping 位置，诊断命令提示只根据已验证 preset 生成
- token 保持在 Rust 后端与系统钥匙串边界内；Globalping 请求只发往固定 `api.globalping.io` HTTPS API
- 启用 `inProgressUpdates` 并按 session ID 过滤事件；ETag / 304、700 ms 轮询、8 秒单请求 / 20 秒总等待和取消语义与 DNS 一致
- 成功响应 JSON 按解压后的实际流量限制为 512 KiB；`Content-Length` 超限提前拒绝，分块响应越限停止读取；畸大或无效 JSON 显示请求失败且不丢弃已完成的本机 / 远端结果
- 多节点顶栏选择器不会暗示普通 Ping / HTTP 面板已支持远程路由；远程 Globalping 操作只从多节点面板触发

### 档位

Post-MVP-C
