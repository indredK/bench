## S-X-01 · L1/L2 导航记忆与结果保留

### 背景

用户在「基础 · 体检」与「测试 · Ping」间来回对比。

### 步骤

1. 基础视角选 L2「一键体检」并跑完
2. 切到测试 → Ping 并跑完
3. 回到基础视角 → 应仍停在「一键体检」，结果仍在
4. 进入站点延迟 → 常用官网，分别测试两张卡片
5. 切到测试 → Ping，再回到站点延迟 → 常用官网 → 两张卡片结果仍在
6. 点击「测试全部」→ 旧结果按本包清除，新样本逐张出现；取消时已完成卡片结果保留
7. 进入「上不了网 · MTU」后切走再回来 → `offlineSub` 仍为 MTU
8. 离开整个 feature 再进入 → 恢复上次 `l1Id`（若采用 session 记忆）

### 期望

- 符合 design §3.1 导航记忆表
- 切换导航**不**清空各面板最近结果（除非用户清除或新跑覆盖）
- 官方站点单卡结果在 L1/L2 导航往返后保留；单卡重测只替换目标卡，整包重测只清理该包目标
- L2 从树中移除后回退到该 L1 第一个合法项

## S-X-02 · 命令透明（hover + 日志）

### 背景

开发者想确认按钮实际调用的 IPC。

### 步骤

1. hover 或键盘聚焦「开始体检」/「Ping」等按钮及一个官网单卡 → Tooltip 显示 IPC 契约名和关键参数
2. 单测官网卡片后打开命令日志 → 见实际 command/event 序列与单卡目标
3. 展开某个体检项 → 见 `commandHint`；合成项标明非独立 IPC

### 期望

- 显示契约名（不翻译标识符）；参数脱敏
- 官网单卡提示包含 `startSitesProbe` 和该卡片目标
- 降级路径写明 `// degraded: …`
- 无 token/密钥进日志

### 档位

MVP（design §3.5）

## S-X-03 · 高危重置网络栈三次确认

### 背景

用户尝试「一键修复 → 重置网络栈」。

### 步骤

1. 打开修复面板 → 选择 `resetNetworkStack`
2. 走完三步：影响说明 → 参数/后果 → 勾选或确认词
3. 在第 2 步取消；再次进入须从头
4. 完成执行后后端复核；重复执行幂等

对照：

- `flushDns`：单次确认即可
- `switchDns` / `renewDhcp`：≥两步

### 期望

- 三步状态机，而非三个无关联 Alert
- 前端「confirmed=true」不能绕过后端校验
- 成功/失败均有结构化反馈

### 档位

MVP

## S-X-04 · 无特权 / 本地网络权限降级

### 背景

标准用户、未授「本地网络」、无 admin。

### 步骤

1. `getNetworkProbeCapabilities()` 记录 privilege 与各 tool 状态
2. Ping 局域网主机、Traceroute、（若有）SYN/ARP
3. 观察 UI 灰显与文案；引导系统设置隐私项

### 期望

- 矩阵驱动，禁止硬编码全绿
- traceroute 无特权不假装成功
- Ping 失败时提示本地网络权限可能性（不误报为「网络已断」唯一结论）
- ICMP socket 初始化失败时显示本地化权限说明，并提供打开系统网络设置的入口
- HTTP/TCP/DNS 等免特权路径仍可用

### 档位

MVP（Post 能力同理标 `U`/`D`/`missing_pack`）

## S-X-05 · 可选能力包安装与卸载（D-017）

### 背景

用户安装后又想卸载 `pcap-diag`，保持主包轻量。

### 步骤

1. 触发缺包功能 → 安装向导
2. 校验失败（故意坏 hash 的测试通道或 mock）→ 安装失败且不执行二进制
3. 安装成功 → 功能可用
4. 「管理组件」卸载 → capabilities 回到 `missing_pack`
5. 确认 MVP 工具（体检/Ping）**从不**走安装墙

### 期望

- `installCapabilityPack(packId)` 无 URL 参数
- Gatekeeper/ad-hoc 提示符合 D-010
- 与 app-manager 更新安全同级：canonical manifest

### 档位

Post-MVP-Adv

## S-X-06 · 硬红线负向：不出现攻击能力

### 背景

安全评审 / 合规检查。

### 步骤

1. 遍历安全/发现全部 L2 与菜单
2. 搜索设置、命令面板、隐藏路由
3. 代码/契约审计：无攻击类 command 名

### 档位

## S-X-07 · 与 port-manager / diagnostics 边界

### 背景

同一主机既要看「本机谁占用了 8080」，又要看「局域网 NAS 的 22 是否开」。

### 步骤

1. 在 **port-manager**：扫本机端口，见 PID，可 Kill（二次确认）
2. 在 **network-probe**：对 NAS `:22` 做 TCP/端口存活；确认无 Kill
3. 从旧 diagnostics / system-settings ping 入口进入：应跳转或薄封装到 `net_probe`，非第二套算法

### 期望

- 占用/Kill ≠ 外部存活探测
- 禁止长期双份 ping 实现（design §13）

### 档位

MVP（边界在实现期强制）

## S-X-08 · 总览加载失败后手动恢复

### 背景

首次打开总览时本机信息读取失败，用户需要看清错误并决定何时重试。

### 步骤

1. 进入基础视角 → 总览自动加载一次
2. 让任一总览数据读取失败 → 查看错误提示与空态
3. 等待数秒 → 确认没有自动连续请求
4. 点击「刷新」 → 只发起一次重试；恢复后展示最新数据

### 期望

- 首次打开自动加载一次；失败后不循环重试
- 错误提示可见，刷新入口仍可用
- 手动重试清除旧错误；加载期间刷新按钮禁用

### 档位

MVP（P0-1）

## S-X-11 · 报告页清空命令日志前确认

### 背景

报告页与右侧命令日志侧栏共用本会话日志；两个入口都应保护用户免于误清理诊断记录。

### 步骤

1. 运行一次体检，产生本会话命令日志
2. 进入「报告」并点击「清空日志」
3. 选择取消，确认报告页和侧栏中的日志均保留

### 期望

- 报告页与侧栏的清理行为一致，清理前都显示二次确认
- 取消时命令日志不变；确认后两个入口都显示空态
- 日志为空时清理按钮禁用

### 档位

## S-X-12 · 单次探测失败重跑不保留旧结果

### 背景

用户连续测试不同目标时，失败的第二次 Ping、TCP、DNS、自定义目标或 MTU 请求不能让第一次成功结果冒充当前目标的结果。

### 步骤

1. Ping `127.0.0.1` 一次并确认成功结果，再将目标改为 `-bad` 并重跑
2. DNS 查询 `example.com` 的 A 记录并确认成功结果，再将域名改为 `-bad` 并重跑
3. TCP 连接一个可达的本机 host:port 并确认成功结果，再将主机改为 `-bad` 并重跑
4. 用可达 URL 运行自定义目标探测并确认成功结果，再将目标改为 `-bad` 并重跑
5. MTU 探测 `127.0.0.1` 并确认成功结果，再将目标改为 `-bad` 并重跑
6. 查看每轮错误反馈与结果卡；修正输入后确认这些探测均可再次成功运行

### 期望

- 新 Ping、TCP、DNS、自定义目标或 MTU 请求开始时清除对应的上一轮结果
- 无效目标显示本轮失败反馈，不保留上一轮成功结果
- 修正目标后可再次成功运行

### 档位

MVP（P0-1 失败态一致性）

## S-X-13 · 错误反馈归属触发它的工具面板

### 背景

网络探测任务可以并行或在运行中切换面板；某个工具的失败信息不能冒充另一个工具的错误。

### 步骤

1. 在测试 → Ping 输入无效目标 `-bad` 并运行，确认显示 Ping 失败
2. 切换到测试 → DNS，确认 Ping 错误横幅消失
3. 在 DNS 触发失败，再切回 Ping，确认 DNS 错误不显示在 Ping 面板
4. 在离开原面板前启动一个会延迟失败的探测，切换到另一面板，确认晚到的失败仍不显示在新面板
5. 从离线诊断切换 IPv6 / 公网出口等子视图，确认错误只显示在所属子工具

### 期望

- 失败反馈按错误来源映射到对应 L1/L2；取消失败按会话种类定位
- 导航切换清除当前错误；晚到的旧请求失败不误报到当前面板
- 未归类的模块级初始化错误仍可见，不被静默吞掉

### 档位

MVP（P0-1 失败态一致性）

## S-X-14 · 主动探测面板初始空态

### 背景

首次打开测试工具时还没有结果，用户需要知道结果会出现在哪里；请求执行期间或失败时，不应再显示会误导状态的初始空态。

### 步骤

1. 依次打开 Ping、DNS、TCP、自定义目标、Traceroute、MTU、公网出口和带宽测速面板，不启动探测
2. 确认空态引导与输入/运行按钮同时可见
3. 启动一次探测，确认加载期间空态隐藏，结果完成后由结果替换
4. 触发一个无效目标错误，确认所属错误横幅显示且初始空态不重复出现
5. 打开能力不可用或无测速源的状态，确认不显示建议运行但无法执行的空态

### 期望

- 每个可运行的主动探测面板在首次空闲且无结果时显示本地化空态
- 加载中或当前工具失败时不显示初始空态；错误仍由所属面板反馈
- 能力不可用或测速源未就绪时不显示无法执行的引导

### 映射

- UI：`PingPanel` / `DnsLookupPanel` / `TcpConnectPanel` / `ProbeTargetPanel` / `TraceroutePanel` / `MtuPanel` / `EgressPanel` / `SpeedPanel`
- UX：产品规格 §5 测试面板空态

### 档位

MVP（P0-1 空态一致性）

## S-X-15 · 测速失败与取消反馈双语一致

### 背景

测速源不可用或用户取消后，结果卡应依据结构化状态提供清楚的本地化反馈，不重复显示后端英文自由文本。

### 步骤

1. 在测试 → 带宽测速选择不可达的自托管模板并开始测速
2. 等待失败返回，检查结果卡与 30 秒冷却倒计时
3. 选择可用测速源并在运行过程中取消，检查结果卡
4. 分别切换中文和英文，查看不可用与取消两种终态

### 期望

- 不可用结果卡只显示当前语言的测速源不可用反馈；测速源错误进入 30 秒冷却
- 取消结果卡只显示当前语言的已取消反馈；取消成功不进入冷却
- 不把 `SpeedTestResult.message` 后端自由文本原样追加到本地化状态文案旁

### 映射

- UI：`SpeedPanel`
- IPC：`SpeedTestResult.ok` / `cancelled` / `message`
- UX：产品规格 §5 测试工具终态反馈

### 档位

Post-MVP-C（P0-1 状态反馈一致性）

## S-X-16 · TCP 终态本地化与系统详情按需显示

### 背景

TCP 连通探测将稳定状态作为结果主文案；操作系统错误字符串仅作为补充诊断信息，避免默认结果卡混用语言并让关键状态不清楚。

### 步骤

1. 在测试 → TCP 连通输入本机地址 `127.0.0.1` 与未监听的端口 `1`
2. 运行探测，检查失败状态与诊断详情的默认呈现
3. 展开「系统诊断详情」查看操作系统错误
4. 分别切换中文和英文，确认状态及展开入口跟随当前语言

### 期望

- `ok`、`refused`、`unreachable`、`dns_failed`、`timeout` 与 `error` 均显示本地化状态；未知状态显示本地化兜底
- 系统错误详情默认收起，明确标注为系统诊断，并可由用户展开查看
- 失败结果不直接显示原始状态枚举或默认混入 OS 英文错误

### 映射

- UI：`TcpConnectPanel`
- IPC：`TcpConnectResult.status` / `message`
- UX：产品规格 §5 测试工具终态反馈

### 档位

MVP（P0-1 失败态一致性）

## S-X-17 · Ping 实时进度、取消与目标锁定

### 背景

用户发起多包 Ping 后，需要看到逐包反馈，能及时停止长任务，并确认结果始终对应本轮提交的目标。

### 步骤

1. 在测试 → Ping 将目标设为 `127.0.0.1`、次数设为 20 并开始
2. 确认运行中显示已完成包数/总数和逐包结果，目标与次数不可编辑
3. 点击「取消探测」，确认按钮进入本地化的取消中状态
4. 检查终态为已取消，汇总包数与已完成样本一致，且取消后没有新样本追加
5. 将次数设为 1 再运行，确认新会话正常完成且不混入上一轮样本

### 期望

- `scan-session` 与每个 `ping-sample` 使用同一 `sessionId`；迟到或旧会话样本不进入当前结果
- 运行期间持续展示进度和已完成样本，输入锁定，取消请求对当前会话只发送一次
- 取消后返回部分结果并标记 `cancelled`；新一轮开始时清空旧结果与样本
- 中文和英文下的进度、取消入口、取消中与取消完成状态均已本地化

### 映射

- UI：`PingPanel`
- IPC：`pingHost` / `network-probe:scan-session` / `network-probe:ping-sample` / `cancelScan`
- UX：产品规格 §5 Ping 与长任务取消
- 设计：design-test §3.1；design §6.1

### 档位

MVP（P0-1 流式状态与取消一致性）
