## S-X-01 · L1/L2 导航记忆与结果保留

### 背景

用户在「基础 · 体检」与「测试 · Ping」间来回对比。

### 步骤

1. 基础视角选 L2「一键体检」并跑完
2. 切到测试 → Ping 并跑完
3. 回到基础视角 → 应仍停在「一键体检」，结果仍在
4. 进入站点延迟 → 常用官网，分别测试两张卡片
5. 切到测试 → Ping，再回到站点延迟 → 常用官网 → 两张卡片结果仍在
6. 点击「测试全部」→ 旧结果按本包清除，新样本逐张出现；取消时已完成卡片结果保留
7. 进入「上不了网 · MTU」后切走再回来 → `offlineSub` 仍为 MTU
8. 离开整个 feature 再进入 → 恢复上次 `l1Id`（若采用 session 记忆）

### 期望

- 符合 design §3.1 导航记忆表
- 切换导航**不**清空各面板最近结果（除非用户清除或新跑覆盖）
- 官方站点单卡结果在 L1/L2 导航往返后保留；单卡重测只替换目标卡，整包重测只清理该包目标
- L2 从树中移除后回退到该 L1 第一个合法项

## S-X-02 · 命令透明（hover + 日志）

### 背景

- 官网单卡提示包含 `startSitesProbe` 和该卡片目标
- 降级路径写明 `// degraded: …`
- 无 token/密钥进日志

## S-X-03 · 高危重置网络栈三次确认

### 背景

用户尝试「一键修复 → 重置网络栈」。

### 步骤

1. 打开修复面板 → 选择 `resetNetworkStack`
2. 走完三步：影响说明 → 参数/后果 → 勾选或确认词
3. 在第 2 步取消；再次进入须从头
4. 完成执行后后端复核；重复执行幂等

对照：

- `flushDns`：单次确认即可
- `switchDns` / `renewDhcp`：≥两步

### 期望

- 三步状态机，而非三个无关联 Alert
- 前端「confirmed=true」不能绕过后端校验
- 成功/失败均有结构化反馈

### 档位

MVP

## S-X-04 · 无特权 / 本地网络权限降级

### 背景

标准用户、未授「本地网络」、无 admin。

### 步骤

1. `getNetworkProbeCapabilities()` 记录 privilege 与各 tool 状态
2. Ping 局域网主机、Traceroute、（若有）SYN/ARP
3. 观察 UI 灰显与文案；引导系统设置隐私项

### 期望

- 矩阵驱动，禁止硬编码全绿
- traceroute 无特权不假装成功
- Ping 失败时提示本地网络权限可能性（不误报为「网络已断」唯一结论）
- ICMP socket 初始化失败时显示本地化权限说明，并提供打开系统网络设置的入口
- HTTP/TCP/DNS 等免特权路径仍可用

### 档位

MVP（Post 能力同理标 `U`/`D`/`missing_pack`）

## S-X-07 · 与 port-manager / diagnostics 边界

### 背景

同一主机既要看「本机谁占用了 8080」，又要看「局域网 NAS 的 22 是否开」。

### 步骤

1. 在 **port-manager**：扫本机端口，见 PID，可 Kill（二次确认）
2. 在 **network-probe**：对 NAS `:22` 做 TCP/端口存活；确认无 Kill
3. 从旧 diagnostics / system-settings ping 入口进入：应跳转或薄封装到 `net_probe`，非第二套算法

### 期望

- 占用/Kill ≠ 外部存活探测
- 禁止长期双份 ping 实现（design §13）

### 档位

MVP（边界在实现期强制）

## S-X-08 · 总览加载失败后手动恢复

### 背景

首次打开总览时本机信息读取失败，用户需要看清错误并决定何时重试。

### 步骤

1. 进入基础视角 → 总览自动加载一次
2. 让任一总览数据读取失败 → 查看错误提示与空态
3. 等待数秒 → 确认没有自动连续请求
4. 点击「刷新」 → 只发起一次重试；恢复后展示最新数据

### 期望

- 首次打开自动加载一次；失败后不循环重试
- 错误提示可见，刷新入口仍可用
- 手动重试清除旧错误；加载期间刷新按钮禁用

### 档位

MVP（P0-1）

## S-X-12 · 单次探测失败重跑不保留旧结果

### 背景

用户连续运行单次探测时，失败的后续请求不能让第一次成功结果冒充当前结果；这也适用于离线诊断整组结果，以及安全、发现面板中的结果卡。

### 步骤

1. Ping `127.0.0.1` 一次并确认成功结果，再将目标改为 `-bad` 并重跑
2. DNS 查询 `example.com` 的 A 记录并确认成功结果，再将域名改为 `-bad` 并重跑
3. TCP 连接一个可达的本机 host:port 并确认成功结果，再将主机改为 `-bad` 并重跑
4. 用可达 URL 运行自定义目标探测并确认成功结果，再将目标改为 `-bad` 并重跑
5. MTU 探测 `127.0.0.1` 并确认成功结果，再将目标改为 `-bad` 并重跑
6. 查询公网 IP 并确认结果，再触发一次失败的公网 IP 刷新
7. 跑成功一轮「上不了网」完整诊断，再让任一子请求失败并重跑
8. 在多节点 DNS 对比中先显示结果，再触发一次受控失败；确认旧答案卡消失
9. 对污染检测、WHOIS、DNSSEC、NAT、NTP、ARP 发现、局域网服务浏览和抓包诊断，分别运行成功一次，再触发失败重跑
10. 查看错误反馈与结果卡；修正输入或条件后确认探测可再次运行

### 期望

- 新 Ping、TCP、DNS、自定义目标或 MTU 请求开始时清除对应的上一轮结果
- 新公网 IP 刷新开始时清除旧 IP；完整离线诊断开始时一并清除 Captive、公网 IP、代理/VPN、IPv6 和 MTU 的上一轮结果
- 污染检测、WHOIS、DNSSEC、NAT、NTP、ARP 发现、局域网服务浏览、抓包诊断和多节点 DNS 的新请求开始时清除各自旧结果
- 无效目标显示本轮失败反馈，不保留上一轮成功结果
- 离线诊断任一子请求失败时不显示来自上一轮的卡片，且错误反馈和重试入口仍可见
- 修正目标后可再次成功运行

### 档位

MVP（P0-1 失败态一致性）

## S-X-22 · Quick Fix 结果本地化与系统详情折叠

### 背景

用户在中文或英文界面运行 Quick Fix，后端会返回稳定动作键和操作系统原始反馈。

1. 在 Quick Fix 中准备一条成功和一条失败结果，反馈分别包含英文系统消息。

- 动作名和成功/失败状态随当前语言本地化，不把稳定 IPC key 当用户标题。

- 命令提示保持可读，未知动作键不泄漏到主结果。

### 映射

- UI：`FixPanel` / `FixResult`
- IPC：`flushDns` / `switchDns` / `renewDhcp` / `resetNetworkStack`

## S-X-13 · 错误反馈归属触发它的工具面板

### 背景

网络探测任务可以并行或在运行中切换面板；某个工具的失败信息不能冒充另一个工具的错误。

### 步骤

1. 在测试 → Ping 输入无效目标 `-bad` 并运行，确认显示 Ping 失败
2. 切换到测试 → DNS，确认 Ping 错误横幅消失
3. 在 DNS 触发失败，再切回 Ping，确认 DNS 错误不显示在 Ping 面板
4. 先启动 DNS 查询，再切换到 TCP 并触发 TCP 失败；DNS 晚到失败时确认当前 TCP 错误仍保留
5. 在离开原面板前启动一个会延迟失败的探测，切换到另一面板，确认晚到的失败仍不显示在新面板
6. 从离线诊断切换 IPv6 / 公网出口等子视图，确认错误只显示在所属子工具

### 期望

- 失败反馈按错误来源映射到对应 L1/L2；取消失败按会话种类定位
- 导航切换清除当前错误；晚到的旧请求失败不误报到当前面板
- 当前面板已有可见错误时，其他面板的迟到错误不得覆盖它
- 未归类的模块级初始化错误仍可见，不被静默吞掉

### 档位

MVP（P0-1 失败态一致性）

## S-X-14 · 主动探测面板初始空态

### 背景

首次打开测试工具时还没有结果，用户需要知道结果会出现在哪里；请求执行期间或失败时，不应再显示会误导状态的初始空态。

### 步骤

1. 依次打开 Ping、DNS、TCP、自定义目标、Traceroute、MTU、公网出口和带宽测速面板，不启动探测
2. 确认空态引导与输入/运行按钮同时可见
3. 启动一次探测，确认加载期间空态隐藏，结果完成后由结果替换
4. 触发一个无效目标错误，确认所属错误横幅显示且初始空态不重复出现
5. 打开能力不可用或无测速源的状态，确认不显示建议运行但无法执行的空态

### 期望

- 每个可运行的主动探测面板在首次空闲且无结果时显示本地化空态
- 加载中或当前工具失败时不显示初始空态；错误仍由所属面板反馈
- 能力不可用或测速源未就绪时不显示无法执行的引导

### 映射

- UI：`PingPanel` / `DnsLookupPanel` / `TcpConnectPanel` / `ProbeTargetPanel` / `TraceroutePanel` / `MtuPanel` / `EgressPanel` / `SpeedPanel`
- UX：产品规格 §5 测试面板空态

### 档位

MVP（P0-1 空态一致性）

## S-X-15 · 测速失败与取消反馈双语一致

### 背景

测速源不可用或用户取消后，结果卡应依据结构化状态提供清楚的本地化反馈，不重复显示后端英文自由文本。

### 步骤

1. 在测试 → 带宽测速选择不可达的自托管模板并开始测速
2. 等待失败返回，检查结果卡与 30 秒冷却倒计时
3. 选择可用测速源并在运行过程中取消，检查结果卡
4. 分别切换中文和英文，查看不可用与取消两种终态

### 期望

- 不可用结果卡只显示当前语言的测速源不可用反馈；测速源错误进入 30 秒冷却
- 取消结果卡只显示当前语言的已取消反馈；取消成功不进入冷却
- 不把 `SpeedTestResult.message` 后端自由文本原样追加到本地化状态文案旁

### 映射

- UI：`SpeedPanel`
- IPC：`SpeedTestResult.ok` / `cancelled` / `message`
- UX：产品规格 §5 测试工具终态反馈

### 档位

Post-MVP-C（P0-1 状态反馈一致性）

## S-X-16 · TCP 终态本地化与系统详情按需显示

### 背景

TCP 连通探测将稳定状态作为结果主文案；操作系统错误字符串仅作为补充诊断信息，避免默认结果卡混用语言并让关键状态不清楚。

### 步骤

1. 在测试 → TCP 连通输入本机地址 `127.0.0.1` 与未监听的端口 `1`
2. 运行探测，检查失败状态与诊断详情的默认呈现
3. 展开「系统诊断详情」查看操作系统错误
4. 分别切换中文和英文，确认状态及展开入口跟随当前语言

### 期望

- `ok`、`refused`、`unreachable`、`dns_failed`、`timeout` 与 `error` 均显示本地化状态；未知状态显示本地化兜底
- 系统错误详情默认收起，明确标注为系统诊断，并可由用户展开查看
- 失败结果不直接显示原始状态枚举或默认混入 OS 英文错误

### 映射

- UI：`TcpConnectPanel`
- IPC：`TcpConnectResult.status` / `message`
- UX：产品规格 §5 测试工具终态反馈

### 档位

MVP（P0-1 失败态一致性）

## S-X-17 · Ping 实时进度、取消与目标锁定

### 背景

用户发起多包 Ping 后，需要看到逐包反馈，能及时停止长任务，并确认结果始终对应本轮提交的目标。

### 步骤

1. 在测试 → Ping 将目标设为 `127.0.0.1`、次数设为 20 并开始
2. 确认运行中显示已完成包数/总数和逐包结果，目标与次数不可编辑
3. 点击「取消探测」，确认按钮进入本地化的取消中状态
4. 检查终态为已取消，汇总包数与已完成样本一致，且取消后没有新样本追加
5. 将次数设为 1 再运行，确认新会话正常完成且不混入上一轮样本

### 期望

- `scan-session` 与每个 `ping-sample` 使用同一 `sessionId`；迟到或旧会话样本不进入当前结果
- 运行期间持续展示进度和已完成样本，输入锁定，取消请求对当前会话只发送一次
- 取消后返回部分结果并标记 `cancelled`；新一轮开始时清空旧结果与样本
- 中文和英文下的进度、取消入口、取消中与取消完成状态均已本地化

### 映射

- UI：`PingPanel`
- IPC：`pingHost` / `network-probe:scan-session` / `network-probe:ping-sample` / `cancelScan`
- UX：产品规格 §5 Ping 与长任务取消
- 设计：design-test §3.1；design §6.1

### 档位

MVP（P0-1 流式状态与取消一致性）

## S-X-18 · Quick Fix 服务加载重试与操作防重入

### 背景

Quick Fix 依赖操作系统返回网络服务列表才能执行修复。首次读取失败或列表为空时，用户需要看到明确状态并能在当前页面重试；列表刷新和系统设置跳转都应防止重复请求。

### 步骤

1. 首次进入 Quick Fix，观察网络服务列表的读取状态。
2. 在加载完成前快速触发刷新；确认下拉框与刷新按钮禁用，且只执行一个服务列表请求。
3. 读取失败或返回空列表时，确认显示明确空态并保留可用的再次读取入口。
4. 已有服务后刷新失败，确认原列表仍可见、错误横幅可辨认；再次刷新成功后列表更新。
5. 快速连续点击「打开系统网络设置」，确认只派发一个未完成的打开请求，并显示进行中状态。

### 期望

- 加载、空列表、失败和成功状态可区分；读取失败后可在当前面板重试。
- 刷新失败不清除已显示的服务列表。
- 当前选择的服务若在刷新后消失，清除过期选择并禁用依赖服务的修复动作；即使还有其他服务，也要求用户明确重新选择，避免把修复静默切到另一块网卡。
- 同一服务读取或设置打开请求尚未结束时，不重复派发 IPC。
- 此场景只读取网络服务并打开系统设置，不修改系统网络配置。

### 映射

- UI：`FixPanel` / `OverviewPanel`
- IPC：`listNetworkServices` / `openSystemNetworkSettings`
- UX：coding §3/§5；产品规格 §13.3

### 档位

MVP（P0-1 加载、失败与重入一致性）

## S-X-19 · 自定义目标协议失败本地化与诊断折叠

### 背景

自定义目标探测可能同时返回 ICMP、HTTP 与 TLS 失败。依赖库原始错误通常是英文，直接放在结果主行会造成界面语言混杂，也会让传输层细节抢占用户首先需要的状态说明。

### 步骤

1. 在英文和中文界面分别对不可达目标（例如 `192.0.2.1`）运行自定义目标探测。
2. 确认 ICMP、HTTP 传输失败和 TLS 握手失败主状态均按当前语言显示。
3. 确认原始 ICMP / reqwest / TLS 诊断不出现在主状态行中。
4. 展开「系统诊断详情」，确认可读到对应协议的原始错误；再次收起后主结果仍保持本地化。
5. 对返回 HTTP 5xx 状态码的目标运行探测，确认主状态显示本地化 HTTP 状态码，原始 transport 错误仍默认折叠。

### 期望

- 网络库自由文本不直接作为 ICMP、HTTP 或 TLS 的主状态文案。
- HTTP 状态码失败显示状态码；未取得状态码的请求失败显示本地化通用请求失败。
- TLS 失败主状态本地化为握手未完成。
- 未识别 ICMP 错误、HTTP 错误和 TLS 握手诊断集中显示在默认关闭的系统详情中。
- 中文和英文均无未经本地化的依赖错误泄漏。

### 映射

- UI：`ProbeTargetPanel`
- IPC：`probeTarget`
- UX：产品规格 §5 自定义目标与错误详情
- 设计：design-test §3.4

### 档位

MVP（P0-1 失败态与诊断一致性）

## S-X-20 · Ping 单包系统错误本地化

### 背景

Ping 逐包结果来自系统和 ICMP 依赖库；直接显示原始错误会把英文系统信息泄漏到中文界面，而且错误文本随平台和依赖版本变化，不适合作为 UI 契约。

### 步骤

1. 在 macOS 中文界面的测试 → Ping 中对无响应目标（例如 `192.0.2.1`）发送 1 个包。
2. 确认逐包结果显示本地化的超时状态，且不出现 `Request timeout for icmp_seq` 等系统英文原文。
3. 切换英文界面并重新运行同一目标，确认逐包状态显示 `Request timed out`。
4. 通过组件与 Rust 分类测试确认 `permission_denied` 和 `network_error` 也使用固定错误码映射，不依赖系统自由文本。

### 期望

- Ping IPC 的失败样本只返回稳定分类码：`timeout`、`permission_denied` 或 `network_error`。
- UI 根据当前语言映射失败状态；依赖库错误文本不进入逐包主结果。
- 错误码未知时以本地化通用错误回退。

### 映射

- UI：`PingPanel`
- IPC：`pingHost` / `network-probe:ping-sample`
- UX：产品规格 §5 Ping
- 设计：design-test §3.1

### 档位

MVP（P0-1 失败态与本地化一致性）

## S-X-21 · Quick Fix 失败重跑清除旧操作结果

### 背景

Quick Fix 上一项操作成功后，下一次操作失败时，界面不能把上一项成功结果留在本轮错误旁边。

### 步骤

1. 在隔离 QA 中让「刷新 DNS」受控返回成功，并确认显示成功结果卡。
2. 再次运行同一操作，让 IPC 受控失败；不执行真实系统网络修复。
3. 检查结果卡与错误横幅。

### 期望

- 每个 Quick Fix 操作起跑时清除上一操作结果。
- 失败时只显示本轮错误，不保留旧成功或失败结果卡。
- 运行期间按钮禁用，结束后可再次操作。

### 映射

- UI：`FixPanel`
- IPC：`flushDns` / `switchDns` / `renewDhcp` / `resetNetworkStack`
- UX：产品规格 §13.3

### 档位

MVP（P0-1 失败态一致性）
