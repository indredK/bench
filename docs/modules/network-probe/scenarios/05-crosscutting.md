## S-X-01 · L1/L2 导航记忆与结果保留

### 背景

用户在「基础 · 体检」与「测试 · Ping」间来回对比。

### 步骤

1. 基础视角选 L2「一键体检」并跑完
2. 切到测试 → Ping 并跑完
3. 回到基础视角 → 应仍停在「一键体检」，结果仍在
4. 进入站点延迟 → 常用官网，分别测试两张卡片
5. 切到测试 → Ping，再回到站点延迟 → 常用官网 → 两张卡片结果仍在
6. 点击「测试全部」→ 旧结果按本包清除，新样本逐张出现；取消时已完成卡片结果保留
7. 进入「上不了网 · MTU」后切走再回来 → `offlineSub` 仍为 MTU
8. 离开整个 feature 再进入 → 恢复上次 `l1Id`（若采用 session 记忆）

### 期望

- 符合 design §3.1 导航记忆表
- 切换导航**不**清空各面板最近结果（除非用户清除或新跑覆盖）
- 官方站点单卡结果在 L1/L2 导航往返后保留；单卡重测只替换目标卡，整包重测只清理该包目标
- L2 从树中移除后回退到该 L1 第一个合法项

## S-X-03 · 高危重置网络栈三次确认

### 背景

用户尝试「一键修复 → 重置网络栈」。

### 步骤

1. 打开修复面板 → 选择 `resetNetworkStack`
2. 走完三步：影响说明 → 参数/后果 → 勾选或确认词
3. 在第 2 步取消；再次进入须从头
4. 完成执行后后端复核；重复执行幂等

对照：

- `flushDns`：单次确认即可
- `switchDns` / `renewDhcp`：≥两步

### 期望

- 三步状态机，而非三个无关联 Alert
- 前端「confirmed=true」不能绕过后端校验
- 后端在任何副作用前校验一次服务白名单，并在 DHCP 阶段复用已校验的服务；不得在 DNS 刷新后重新读取服务列表
- DNS 刷新与 DHCP 续租有部分成功时，结果仍明确显示两步的结构化反馈
- 每次调用均独立校验；重复执行不依赖上次调用的内存状态

### 档位

MVP

## S-X-04 · 无特权 / 本地网络权限降级

### 背景

标准用户、未授「本地网络」、无 admin。

### 步骤

1. `getNetworkProbeCapabilities()` 记录 privilege 与各 tool 状态
2. Ping 局域网主机、Traceroute、（若有）SYN/ARP
3. 观察 UI 灰显与文案；引导系统设置隐私项
4. Ping 样本为 `permission_denied` 时打开权限入口，确认进入“隐私与安全性”；普通超时不提供该入口

### 期望

- 矩阵驱动，禁止硬编码全绿
- traceroute 无特权不假装成功
- Ping 失败时提示本地网络权限可能性（不误报为「网络已断」唯一结论）
- ICMP socket 初始化失败时显示本地化权限说明，并提供打开“系统设置 → 隐私与安全性”的入口；Ping 单包为 `permission_denied` 时显示相同入口，普通超时不显示权限操作
- macOS Local Network 使用说明随应用 Info.plist 提供中英文版本；用户自行进入“本地网络”检查 Bench 授权
- HTTP/TCP/DNS 等免特权路径仍可用

### 档位

MVP（Post 能力同理标 `U`/`D`/`missing_pack`）

## S-X-05 · 可选能力包安装与卸载（D-017）

### 背景

用户安装后又想卸载 `pcap-diag`，保持主包轻量。

### 步骤

1. 触发缺包功能 → 安装向导
2. 校验失败（后端返回真实 hash 错误或开发验证通道）→ 对话框显示本地化失败状态，原始诊断默认收起，能力包仍为未安装且不执行二进制
3. 安装成功 → 功能可用
4. 「管理组件」卸载 → capabilities 回到 `missing_pack`
5. 确认 MVP 工具（体检/Ping）**从不**走安装墙

### 期望

- `installCapabilityPack(packId)` 无 URL 参数
- Gatekeeper/ad-hoc 提示符合 D-010
- 与 app-manager 更新安全同级：canonical manifest
- 失败反馈必须区分 `hash-mismatch` 与普通失败；关闭并重开管理对话框后不残留旧结果
- 哈希失败测试按钮仅开发构建或显式 QA 构建可见，普通发布构建不显示

## S-X-07 · 与 port-manager / diagnostics 边界

### 背景

同一主机既要看「本机谁占用了 8080」，又要看「局域网 NAS 的 22 是否开」。

### 步骤

1. 在 **port-manager**：扫本机端口，见 PID，可 Kill（二次确认）
2. 在 **network-probe**：对 NAS `:22` 做 TCP/端口存活；确认无 Kill
3. 从旧 diagnostics / system-settings ping 入口进入：应跳转或薄封装到 `net_probe`，非第二套算法

### 期望

- 占用/Kill ≠ 外部存活探测
- 禁止长期双份 ping 实现（design §13）

### 档位

MVP（边界在实现期强制）

## S-X-08 · 总览加载失败后手动恢复

### 期望

- 首次打开自动加载一次；失败后不循环重试
- 错误提示可见，刷新入口仍可用
- 手动重试清除旧错误；加载期间刷新按钮禁用

### 档位

## S-X-12 · 单次探测失败重跑不保留旧结果

### 背景

用户连续运行单次探测时，失败的后续请求不能让第一次成功结果冒充当前结果；这也适用于离线诊断整组结果，以及安全、发现面板中的结果卡。

### 步骤

1. Ping `127.0.0.1` 一次并确认成功结果，再将目标改为 `-bad` 并重跑
2. DNS 查询 `example.com` 的 A 记录并确认成功结果，再将域名改为 `-bad` 并重跑
3. TCP 连接一个可达的本机 host:port 并确认成功结果，再将主机改为 `-bad` 并重跑
4. 用可达 URL 运行自定义目标探测并确认成功结果，再将目标改为 `-bad` 并重跑
5. MTU 探测 `127.0.0.1` 并确认成功结果，再将目标改为 `-bad` 并重跑
6. 查询公网 IP 并确认结果，再触发一次失败的公网 IP 刷新
7. 跑成功一轮「上不了网」完整诊断，再让任一子请求失败并重跑
8. 在多节点 DNS 对比中先显示结果，再触发一次受控失败；确认旧答案卡消失
9. 对污染检测、WHOIS、DNSSEC、NAT、NTP、ARP 发现、局域网服务浏览和抓包诊断，分别运行成功一次，再触发失败重跑
10. 查看错误反馈与结果卡；修正输入或条件后确认探测可再次运行

### 期望

- 新 Ping、TCP、DNS、自定义目标或 MTU 请求开始时清除对应的上一轮结果
- 新公网 IP 刷新开始时清除旧 IP；完整离线诊断开始时一并清除 Captive、公网 IP、代理/VPN、IPv6 和 MTU 的上一轮结果
- 污染检测、WHOIS、DNSSEC、NAT、NTP、ARP 发现、局域网服务浏览、抓包诊断和多节点 DNS 的新请求开始时清除各自旧结果
- 无效目标显示本轮失败反馈，不保留上一轮成功结果
- 离线诊断任一子请求失败时不显示来自上一轮的卡片，且错误反馈和重试入口仍可见
- 修正目标后可再次成功运行

### 档位

MVP（P0-1 失败态一致性）

## S-X-29 · DNS 刷新部分失败不得报告成功

### 背景

macOS 的 DNS 刷新包含缓存刷新与 mDNSResponder 通知两步；其中一步失败时，结果卡必须反映整体未完成，同时保留两步的具体反馈。

### 步骤

1. 在隔离 QA 中让 `dscacheutil -flushcache` 成功、`killall -HUP mDNSResponder` 失败。
2. 检查 Quick Fix 结果状态与默认折叠的系统反馈详情。
3. 让两条命令都成功，再检查结果状态。

### 期望

- 两条命令都会尝试执行，即使第一条失败也继续执行第二条。
- 只有两条命令都成功时，DNS 刷新结果才标记成功。
- 任一步失败都会标记整体失败，并在系统反馈详情中保留两步结果。

### 映射

- UI：`FixPanel` / `FixResult`
- IPC：`flushDns` / `resetNetworkStack`
- Rust：`net_probe::fix::flush_dns`
- 产品规格：§3.5

### 档位

MVP（P0-1 部分失败反馈）

## S-X-23 · 诊断结果状态本地化与系统反馈折叠

### 背景

Traceroute、NTP、局域网服务发现和包级诊断会返回稳定状态与操作系统/网络库自由文本，主结果需要能被普通用户理解，并保留可选排障信息。

### 步骤

1. 受控让 Traceroute 返回 `unavailable` 且没有跳点，确认显示不可用状态而不是“尚无跳点”的初始空态。
2. 受控返回 NTP `warn` 和原始 DNS / 超时详情，确认等级本地化、底层诊断默认折叠。
3. 让 mDNS 浏览返回绑定错误，确认协议错误主状态本地化、原始错误在详情中。
4. 受控返回抓包 `unavailable`，确认模式与状态本地化，tcpdump 原文默认折叠。
5. 展开各面板系统反馈详情，确认排障文本可读；输入未知状态时确认使用本地化兜底。

### 期望

- 未运行的 Traceroute 才显示初始空态；已运行但不可用、取消或无跳点时显示对应终态。
- NTP 严重级别、Traceroute privilege mode、抓包 mode/status 和局域网协议错误按当前语言呈现。
- Rust / OS / 网络库原始输出默认折叠，展开后可查看；固定只读说明只保留一份本地化提示。
- 未知 enum 不直接泄漏 backend 字符串。

### 映射

- UI：`TraceroutePanel` / `NtpPanel` / `LanServicesPanel` / `PcapDiagPanel` / `ProbeSystemDetails`
- IPC：`startTraceroute` / `probeNtp` / `browseLanServices` / `runPcapDiag`
- 产品规格：§2 / §5 / §6 / §7

### 档位

MVP + Post-MVP-Adv（横切本地化与反馈一致性）

## S-X-24 · 污染检测结果本地化与风险置信度

### 背景

污染检测汇总 DNS、hosts、HTTPS、路由和 ARP 线索。网络库原文和后端 enum 不适合作为主结果；单次网络失败或共享 MAC 也不足以构成攻击结论。

### 步骤

1. 受控返回 DNS resolver 失败、hosts 覆盖、HTTPS 成功/失败、代理路由和共享 ARP MAC 等发现，分别检查中英文主结果。
2. 让 HTTPS 请求因超时、DNS、代理和证书错误失败，确认均显示“无法验证”警告，不能显示高危或断言拦截。
3. 受控返回未知 finding code、kind 和 severity，确认主卡使用本地化兜底。
4. 检查每条原始 evidence 与 command hint 均默认折叠，展开后可供排障。

### 期望

- finding code、种类和严重级别均显示本地化文案；未知值不泄漏 backend 字符串。
- HTTPS 请求失败统一说明单凭该失败不能证明 TLS 拦截，风险级别不高于 warn。
- ARP 快照中同 MAC 被多个 IP 使用仅作为 info 线索，不称为欺骗；单次缓存不声称检测了随时间漂移。
- 原始证据和命令提示默认折叠；产品规格明确 HTTPS / ARP 置信度边界。

### 映射

- UI：`PollutionPanel` / `ProbeSystemDetails`
- IPC：`runPollutionCheck`
- 后端：`PollutionFinding` / `check_ssl_light` / `detect_arp_spoofing_hints`
- 产品规格：§6

### 档位

Post-Adv（安全诊断准确性与结果可读性）

## S-X-25 · 多节点状态本地化与长端点布局

### 背景

用户在中文或英文界面查看本机、Globalping 和自有 agent 节点，并对比多地 DNS 结果。节点类型是 IPC 稳定值，agent URL 可能很长。

### 步骤

1. 准备 `local`、`remote-proxy`、`remote-agent` 和未知节点类型，检查节点列表标签。
2. 使用长度接近后端上限的 agent endpoint，缩窄窗口并检查列表布局；悬停端点查看完整地址。
3. 查看成功与失败的多节点 DNS 结果，并分别切换中文和英文。

### 期望

- 固定节点名和 DNS 成功/失败状态随界面语言翻译；未知类型显示本地化兜底，不泄漏 IPC 原值。
- Globalping 内部 endpoint 不显示给用户；自有 agent 的长端点不会撑宽页面或挤压移除按钮，默认截断，悬停提示保留完整地址。
- 成功和失败状态有清晰、易辨的视觉差异。

### 映射

- UI：`MultiNodePanel`
- IPC：`listProbeNodes` / `compareDnsMulti`
- 产品规格：§7 `nodes`

### 档位

Post-C（多节点结果可读性与响应式布局）

## S-X-26 · Globalping 空答案不得误报成功

### 背景
